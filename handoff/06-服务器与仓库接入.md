### 拿仓库的三种方法（按顺序）

1. **部署密钥握手（首选）**
   ```bash
   mkdir -p /workspace/.keys
   ssh-keygen -t ed25519 -N "" -C k408-github-deploy-new -f /workspace/.keys/k408_github_deploy
   chmod 600 /workspace/.keys/k408_github_deploy
   cat /workspace/.keys/k408_github_deploy.pub
   ```
   只把 `.pub` 那一行发给大哥。大哥在仓库 Settings → Deploy keys → Add deploy key 粘贴并勾选 Allow write access。然后：
   ```bash
   export GIT_SSH_COMMAND="ssh -i /workspace/.keys/k408_github_deploy -o IdentitiesOnly=yes"
   git ls-remote git@github.com:pluto-da/k408-lab.git
   git clone git@github.com:pluto-da/k408-lab.git /workspace/fullstack-408
   git clone -b archive --single-branch git@github.com:pluto-da/k408-lab.git /workspace/k408-archive
   ```
   `ls-remote` 应看到 `refs/heads/master`、`refs/heads/archive`、`refs/tags/v20`。GitHub 的 SSH 主机指纹第一次会提示确认，属正常。
2. **GitHub 连接（备选）**：大哥在新账号连接 GitHub 后，如果你的连接能看到这个私有仓库，可以直接读。旧账号的连接只有读权限、看不到私有仓库也推不上去，所以推送仍走部署密钥。
3. **bundle（兜底）**：大哥上传迁移包里的 `k408-full-v20.bundle`：
   ```bash
   git clone k408-full-v20.bundle /workspace/fullstack-408
   cd /workspace/fullstack-408 && git remote set-url origin git@github.com:pluto-da/k408-lab.git
   ```

新密钥能推送后，请大哥在 Deploy keys 里删掉旧的 `k408-github-deploy`。旧账号存过的 GitHub 个人访问令牌也请他到 GitHub 吊销。

### 连接方法

1. **公钥握手（首选，旧私钥不搬家）**
   ```bash
   mkdir -p /workspace/.deploy
   ssh-keygen -t ed25519 -N "" -C hark-new-408 -f /workspace/.deploy/k408_server
   chmod 600 /workspace/.deploy/k408_server
   cat /workspace/.deploy/k408_server.pub
   ```
   只把公钥给大哥。大哥任选一种追加到服务器 `/root/.ssh/authorized_keys`：
   - 腾讯云控制台 → 轻量应用服务器 → 登录 → OrcaTerm 免密登录，执行 `echo '公钥' >> /root/.ssh/authorized_keys`；
   - 旧账号还能用时，让旧账号追加。
2. **P0 旧私钥（备选）**：大哥上传 `k408-P0-rescue-20261012.7z`，在对话里告诉你口令。
   ```bash
   mkdir -p /workspace/.deploy/p0 && cd /workspace/.deploy/p0 && 7z x ../k408-P0-rescue-20261012.7z
   chmod 600 keys/hark_408
   ssh -i /workspace/.deploy/p0/keys/hark_408 -o IdentitiesOnly=yes root@154.8.183.93
   ```
   登录后立刻把新生成的公钥追加到 `authorized_keys`，再告诉大哥口令已用完、请他删掉对话里那条消息。P0 里的 `.env`、数据库导出、指纹清单只在需要恢复时用，绝不进 Git、不打印。

### 首次连接与验证

- 首次连接前比对指纹：`ssh-keyscan -t ed25519 154.8.183.93 | ssh-keygen -lf -`，必须是上表的 SHA256 值；不一致就停下报告。
- 验证：
  ```bash
  ssh -i /workspace/.deploy/k408_server -o IdentitiesOnly=yes root@154.8.183.93 \
    'hostname; cd /opt/k408 && docker compose ps; grep BUILD_ID .env | cut -c1-30'
  ```
  应看到 `BUILD_ID=v20-58f206a`，三个容器正常。只打印 BUILD_ID 一行。

## 三、部署与回滚

1. 恢复脚本：`cp -r /workspace/k408-archive/deploy/. /workspace/.deploy/`
2. 环境变量：`export K408_SSH_KEY=/workspace/.deploy/k408_server K408_HOST=154.8.183.93`
3. 自检：`echo 'docker compose -f /opt/k408/docker-compose.yml ps' | python3 /workspace/.deploy/rx.py`
4. 部署模式（沿用 d14/d15）：
   - 本地打源码包（排除 node_modules、dist、.git、.env），`K408_TGZ=<包路径> python3 up.py` 上传到 `/root/k408.tgz`；
   - `sed "s/__BUILD__/v21-<短提交号>/" d14.sh | python3 rx.py`：先给当前镜像打回滚标签、备份源码和 .env，再换源码、后台串行构建（api → caddy，Caddy 编译约 20 分钟），日志在 `/root/d14.log`，完成写 `D14_DONE <返回码>`；
   - 构建失败但旧版仍在线时，修好后用 d15 模式重跑（不重复备份）；
   - 上线后检查首页、/lab、/pc、登录注册、协议页、/api/health 全部 200。
   - 新版本的脚本请复制一份改名（如 d16.sh），并把里面的回滚标签名改成当前线上版本。
5. 回滚：v20 的回滚点是服务器上的 v19 镜像标签和 `/root/k408-src-v19-20261012182702.tgz`，用 `d14-rollback.sh`。
6. 部署前在本地跑 `pnpm audit:ui`（全站遮挡、化身数据、多设备三项审计）、typecheck、lint、test，全过再上线。
