# 考研408可视化学习站 · “实用又好看”改版提示词

## 〇、原话与任务定位

站长原话：“感觉有点花里胡哨，能实用又好看吗。”

你是一名同时懂考研学习场景、前端工程和视觉设计的资深产品设计师兼前端工程师。你要接手一个已经上线的网站：考研 408（数据结构、计算机组成原理、操作系统、计算机网络）可视化学习站，地址 http://154.8.183.93 ，包含首页 `/`、动画实验室 `/lab`、3D 整机拆解 `/pc`、登录 `/login`、注册 `/register`、个人中心 `/profile`、用户协议 `/terms`、隐私政策 `/privacy`。你的任务不是推翻重做，而是在保留全部有效功能的前提下，把整站从“炫技、装饰多、信息分散”调整为“打开就能学、信息清楚、看着舒服、越用越顺手”。

这句话很短，但它同时给了一个否定和一个肯定，必须两边都满足：
- 否定：“花里胡哨”——现在的视觉噪音已经超过了它带来的价值，用户感到被打扰、找不到重点。
- 肯定：“实用又好看”——不是要一个灰白的后台表格，也不是删光动画。“好看”仍然是硬要求，只是好看的来源要从“装饰”换成“秩序、留白、字体、配色克制和细节品质”。

## 一、对这句话的深度解读

### 1. “感觉”：这是第一眼的直觉判断，不是逐条挑刺
用户没有说哪个按钮不好，而是说整体“感觉”。这意味着问题出在全局层面：信息密度、装饰元素的数量、颜色的数量、动效的频率、排版的层级。所以改版必须先做“减法清单”，再做局部修补。验收时也要用“第一眼”来检验：打开首页 3 秒内，用户能否说出“这个网站能帮我干什么、我该点哪里”。

### 2. “有点”：程度是中等，不是全盘否定
“有点”说明基础是好的：3D 整机、动画实验、跨科连线、章节考点这些内容本身有价值，用户愿意用。改版不能把有价值的交互（例如 `/pc` 的手指上滑拆解、实验室的单步演示）砍掉，只去掉不承载信息的表演性元素。原则：每个视觉元素都必须回答“它帮用户学到了什么或少点了一下什么”，回答不了的就删或弱化。

### 3. “花里胡哨”：具体可能指什么
结合现有页面，下列元素最可能被感知为“花”：
- 首页的开机自检滚动文字（`POST 自检 … 正常`），纯氛围，无信息；
- 首页主图上的发光热点、连线动画、彩色小标签，四种以上高饱和颜色同时出现；
- 一屏里三个并列的大按钮（拆开整机 / 跟着数据走一遍 / 进入实验室），主次不清；
- 实验室里的 `§01`、`§02` 编号、“爆炸视图”标签、尺寸标注线、仿工程图纸的纸张底色与粗黑边框，风格感很强但增加阅读负担；
- 每个科目各有一种强调色，叠加章节色块、标签色、按钮色，颜色语义过载；
- 实验室顶部的 3D 主板占据首屏，真正的章节考点和实验要往下滚很久；
- 等式“150 分 = 数据结构 45 + …”用多色斜体呈现，装饰大于信息；
- 过多的悬停动效、脉冲、渐显，以及加载时的多步“载入…”文案。

### 4. “能……吗”：这是请求，也带着一点不确定
用户在问“能不能做到”，说明他担心实用和好看是矛盾的。改版要用结果证明二者不矛盾：同一套设计语言，信息层级清晰，所以实用；比例、留白、字体、颜色克制，所以好看。交付时要给出前后对比，让他一眼看出变化。

### 5. “实用”：对考研学生意味着什么
目标用户是备考 408 的学生，主要在手机、平板上碎片化复习，也会在电脑上系统学习。对他们，“实用”具体是：
- 快：打开快、找得快、点得少。首页到任意一个章节考点或实验不超过 2 次点击；
- 准：考点、分值、易错点一目了然，文字比图形优先；
- 稳：手机上不卡、不误触，横竖屏都能用；
- 可回访：能直接定位到上次看的科目或章节（用锚点、清晰的目录即可，不新增账号依赖功能）；
- 可扫读：标题、要点、易错点分层，扫一眼就能复习。

### 6. “好看”：在这个场景里意味着什么
- 克制：全站一种主色 + 中性灰阶；四个科目色只作为小面积识别标记（左侧色条、小圆点、标签），不再大面积铺色；
- 有秩序：统一的 8px 间距网格、统一圆角（建议 10–12px）、统一阴影（最多两档、很轻）；
- 好字体：中文正文 16px 起，行高 1.7，标题字重 600，层级最多 4 级；数字使用等宽或 tabular-nums；
- 留白：内容最大宽度约 1120px，卡片内边距充足，段落之间呼吸感；
- 细节品质：对齐、图标线宽一致、焦点状态清晰、深浅色对比达到 WCAG AA；
- 动效只用于反馈和过渡（150–250ms），不用于“吸引注意”；尊重 `prefers-reduced-motion`。

### 7. 隐含的期待
- 不要丢功能：3D 拆解、实验、连线、流程演示、账号功能都要还在；
- 不要变慢：改版后首屏体积不增加，最好下降；
- 不要变得像模板：保留“把计算机拆开给你看”这个独特定位，但用更成熟的方式表达；
- 不要出现技术名词：页面文案不提 Three.js、WebGL、高斯泼溅等实现细节。

## 二、设计原则（按优先级）

1. 内容先于装饰：每一屏先放用户要的东西（入口、考点、实验），装饰只能是背景层级。
2. 一屏一个主操作：每个区块只有一个最显眼的按钮，其他是次级或文字链接。
3. 颜色有语义：主色 = 可点击/当前状态；科目色 = 科目识别；红/绿 = 对错与警示；其余一律中性。
4. 少即是多：删除不承载信息的元素，合并重复入口，同一信息只出现一次。
5. 移动优先：先在 390×844 手机竖屏上设计，再扩展到平板和桌面。
6. 可访问：键盘可达、焦点可见、对比度达标、触控目标 ≥ 44px、动效可关闭。
7. 性能是设计的一部分：3D 内容按需加载，首页不加载任何 3D 资源。

## 三、视觉系统规范

### 3.1 颜色
- 背景：`#F7F7F5`（略暖的白），卡片 `#FFFFFF`，分隔线 `rgba(0,0,0,0.08)`；
- 文字：主文字 `#1A1C20`，次文字 `#5B606B`，弱文字 `#8A8F99`；
- 主色：一种沉稳的蓝或墨绿（建议 `#2F5BEA` 或现有 `--cn` 的提亮版），用于主按钮、链接、选中态；
- 科目色保留现有色相，但降低饱和度并只用于：卡片左侧 3px 色条、6px 圆点、标签文字色；
- 成功 `#1F7A4D`，错误 `#B3261E`；
- 不再使用纸张底纹、粗黑描边、工程图纸风格的标注线。
- 顶部导航从深黑底改为白底 + 细分隔线，减少视觉重量（3D 页 `/pc` 可保留深色以衬托模型，但控件风格统一）。

### 3.2 字体与排版
- 字体栈保持：Geist + PingFang SC / Noto Sans SC / 微软雅黑；
- 字号：正文 16px（手机 15px），小字 13px，H1 32–40px（手机 26–28px），H2 22–24px，H3 17–18px；
- 行高：正文 1.7，标题 1.3；
- 去掉 `§01` 之类的编号前缀，标题用自然语言；
- 中文标题避免单字换行（使用 `text-wrap: balance` 并兼容回退）。

### 3.3 组件
- 按钮三种：主按钮（实心主色）、次按钮（白底细边框）、文字按钮；高度 44px，圆角 10px；
- 卡片：白底、1px 细边或极轻阴影（`0 1px 2px rgba(0,0,0,.04)`），圆角 12px，悬停只轻微提亮边框；
- 标签：圆角胶囊，浅色底 + 科目色文字；
- 分段控件 / 标签页：用于在科目、章节、实验之间切换；
- 进度与步骤：实验单步演示使用统一的步骤条（上一步 / 播放 / 下一步），按钮位置在全站一致。

### 3.4 动效
- 只保留：页面切换淡入（≤200ms）、展开收起、按钮按下反馈、实验动画本身、3D 拆解本身；
- 删除：开机文字轮播、热点脉冲、首页连线动画、滚动视差、入场逐个飞入。

## 四、逐页改版要求

### 4.1 首页 `/`
目标：3 秒看懂，2 次点击到达任何学习内容。
- 首屏：左侧一句话标题（例如“408 四门课，拆开来学”）+ 一行说明 + 一个主按钮“开始学习”（锚到科目区或进入实验室）+ 一个次按钮“拆开整机”。右侧（桌面）放一张安静的整机静态图，不加热点、不加动画；手机上图片放在文字下方并缩小，或直接省略以保证首屏能看到科目入口。
- 删除开机自检轮播、热点、连线 SVG。
- 第二屏：四门课卡片（2×2 网格，手机 1 列或 2 列），每张卡片显示：科目名、分值、章节数、实验数、最重要的 2–3 个高频考点，点击进入 `/lab#科目`。
- 第三屏：“常用实验”快捷入口，列出 6 个最常用的动画实验（例如排序、二叉树遍历、Dijkstra、页面置换、TCP 拥塞控制、Cache 映射），点击直达实验室对应实验。
- “一次数据的旅程”保留但改为简洁的横向/纵向步骤列表，不用彩色编号块，作为次要内容放在后面，入口指向 `/pc?tour=1`。
- 页脚：用户协议、隐私政策、联系邮箱，一行即可。

### 4.2 实验室 `/lab`
目标：从“展示页”变成“工具页”。
- 页面顶部改为紧凑的工具栏：科目切换（数据结构 / 组成原理 / 操作系统 / 网络）+ 搜索框（按考点或实验名过滤，纯前端）+ 跳转目录。
- 3D 主板不再占据首屏：改为折叠区块“立体结构图”，默认收起，点开才加载模型（按需加载，节省流量和内存）。手机上默认收起。
- 内容区采用“左目录 + 右内容”的两栏布局（桌面），手机上目录变为顶部横向滚动标签或抽屉。
- 章节考点卡：标题、核心考点（列表）、易错点（用浅红底提示框）、对应实验按钮；去掉装饰性编号与图纸风格。
- 动画实验：统一播放控件，统一画布背景（白或极浅灰），统一配色（科目色 + 中性色），控制按钮在手机上固定在底部易触及。
- 流程演示与跨科连线：保留功能，视觉降噪，连线图使用中性线条，仅选中节点高亮。
- “150 分 = …”改成一行朴素的分值表（四个小格子，数字等宽对齐）。
- 加载界面去掉多步“载入…”表演文案，换成一条简洁进度条 + “正在加载实验室”。

### 4.3 整机拆解 `/pc`
目标：保留核心交互，只统一外观。
- 不改手势逻辑（单指上滑拆解、下滑装回、双指旋转缩放），不改 3D 引擎代码；
- 只调整 HUD 的样式：按钮、进度条、说明卡片采用全站组件风格，减少颜色和描边。

### 4.4 登录 / 注册 / 个人中心 / 协议页
- 表单居中卡片，最大宽 400px，标签在输入框上方，错误提示在输入框下方；
- 个人中心分组：账户信息、安全（修改密码、退出所有设备）、危险操作（注销账号，红色次按钮 + 二次确认）；
- 协议页：阅读型排版，最大宽 720px，目录锚点。

## 五、工程约束

- 技术栈不变：React + Vite + TypeScript，`apps/web/src/styles/app.css` 是全站样式入口；实验室旧模块位于 `apps/web/public/legacy`（`body.html`、`css/*.css`、`js/*.js`），改样式优先改 CSS，改结构时同步修改依赖的 JS 选择器，不能让任何实验或演示失效。
- 不修改 `apps/web/src/pc/**` 的引擎与手势逻辑；`Pc.tsx` 只允许改样式类名与外观。
- 首页不得引入任何 3D 依赖；实验室 3D 主板改为点开才加载。
- 设计令牌（颜色、间距、圆角、阴影、字号）集中定义为 CSS 变量，实验室旧样式也引用同一套变量。
- 不新增外部 CDN；字体沿用本地文件。
- 保持 SEO 标题与描述、无障碍属性（skip link、aria、focus）不退化。
- 用户可见文案不出现实现技术名词。

## 六、验收标准

1. 首页首屏（390×844）可见：标题、说明、主按钮，以及至少一张科目卡片的顶部；桌面 1440×900 首屏可见四门课入口。
2. 首页不含任何持续循环的动画；全站同屏高饱和颜色不超过 2 种（科目小标记除外）。
3. 首页到任意章节考点或任意实验 ≤ 2 次点击。
4. 实验室首屏直接出现科目切换和章节内容，而不是 3D 模型；3D 主板展开后功能正常。
5. 所有实验、流程演示、跨科连线、`/pc` 拆解功能与改版前一致。
6. `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm --filter web build` 全部通过。
7. 首页 JS+CSS 传输体积不高于改版前；实验室首屏不再自动下载主板模型。
8. 文字与背景对比度达到 WCAG AA；所有可点击元素触控区域 ≥ 44px；键盘可完整操作。
9. 提供改版前后截图对比：首页、实验室（手机与桌面各一张）。

## 七、执行步骤

1. 盘点：列出现有页面的全部视觉元素，逐个标记“保留 / 简化 / 删除”，理由写一句话。
2. 定令牌：在 `app.css` 顶部建立新设计令牌，旧变量映射到新令牌，避免大面积改动出错。
3. 改首页：按 4.1 重排结构，删除装饰组件，补“常用实验”入口。
4. 改实验室：按 4.2 调整布局与样式，把 3D 主板改为折叠按需加载，统一实验控件。
5. 改账号与协议页：按 4.4 统一表单与阅读排版。
6. 统一 `/pc` HUD 外观。
7. 自测：跑完全部检查命令；用无头浏览器在 390×844、820×1180、1440×900 三个尺寸截图检查对齐、换行、溢出、对比度；逐个点开实验确认无报错。
8. 提交：一次清晰的提交说明，列出删掉了什么、换成了什么。

## 八、交付时向站长说明的内容

- 一句话总结变化：“少了什么、多了什么、哪里更快”；
- 前后对比截图；
- 如有取舍（例如删掉了某个他可能喜欢的动画），说明理由并告知可以恢复。

记住：这次改版的成功标准不是“看起来变了”，而是站长再打开时会说“清爽了，而且我想看的东西一下就找到了”。

## 九、补充：用户画像与典型使用场景

为了让每个设计决定都有依据，请始终带着以下三个具体场景检查方案：

场景一：晚上十一点，宿舍床上，手机竖屏。学生刚做完一套 408 选择题，错了一道页面置换算法的题，想马上看看 LRU 和 OPT 到底怎么走。他需要的是：打开网站，点“操作系统”，找到“页面置换”，直接播放动画，单步看每一次缺页。整个过程不应超过 20 秒，不应该先看到一段开机动画、一块正在加载的 3D 主板，也不应该在一堆彩色按钮里找入口。

场景二：周末下午，图书馆，平板横屏。学生在系统复习计算机组成原理第三章存储系统，想对照教材把 Cache 映射方式、主存与 Cache 的地址划分弄清楚。他需要的是：左边章节目录、右边考点要点，旁边就有可交互的 Cache 映射实验；看完一节能顺手跳到下一节。界面要像一本排版很好的电子书加一个实验台，而不是一张海报。

场景三：第一次被同学推荐打开网站，电脑浏览器。他想在 10 秒内判断这个网站值不值得收藏。他需要的是：一眼看懂“这是 408 的可视化学习工具，有四门课的考点和动画实验，还有一台能拆开的电脑”，并且感觉它做得认真、专业、可信。这里“好看”起决定作用，但好看来自干净和专业，而不是特效。

## 十、反例与正例对照

- 反例：首屏三个同样醒目的按钮。正例：一个主按钮“开始学习”，一个次按钮“拆开整机”，实验室入口放进导航。
- 反例：每个科目一种高饱和底色的大色块卡片。正例：白色卡片，左侧一条细色条，科目名旁一个小圆点。
- 反例：标题前加“§03 · 45 分”的编号。正例：标题“数据结构”，副信息“45 分 · 8 章 · 选择题 1–11 + 2 道综合题”用次级灰色小字。
- 反例：易错点和普通考点混在同一个列表里。正例：易错点单独放进浅色提示框，前面一个小警示图标，一眼就能扫到。
- 反例：加载时依次显示“装配 3D 主板与总线”“连接流程演示”等表演文案。正例：一条进度条，加一句“正在加载实验室”。
- 反例：鼠标悬停时卡片放大、阴影加深、颜色变化同时发生。正例：只轻微改变边框颜色。

## 十一、文案规范

- 用学生的语言，不用宣传腔：写“看 LRU 每一步怎么换页”，不写“沉浸式感受算法之美”；
- 每个按钮文案是一个动作：开始学习、播放、下一步、展开立体图；
- 数字统一使用阿拉伯数字和半角符号，分值、章节数、题号对齐；
- 一句话说明不超过 30 个字，段落不超过 3 行（手机）；
- 不出现“爆炸视图”“影棚模式”这类内部叫法，换成“拆开看”“展示模式”等直白说法；
- 不出现任何实现技术名词。

## 十三、风险与回滚

- 实验室旧脚本依赖大量类名与 DOM 结构，改结构前先用全文搜索确认选择器的使用位置；能用 CSS 达成的不动 HTML。
- 3D 主板改为按需加载后，部件详情、流程演示依赖模型的功能要在模型加载完成后再启用，未加载时按钮应引导用户先展开立体图，或自动展开并加载。
- 所有改动集中在一次提交中，出现问题可以整体回退；不修改数据库与接口。
- 改版后若发现某个被删除的元素其实有用，优先以更克制的方式恢复，而不是原样放回。

## 十四、细节检查清单

- 中文与英文、数字之间加空格；
- 按钮文字不换行，长标题在手机上合理断行；
- 图片设置宽高，避免加载时页面跳动；
- 滚动到锚点时预留顶部导航高度；
- 横屏手机与小屏平板下没有横向滚动条；
- 深浅背景上焦点框都清晰可见；
- 页面标题与描述随路由更新；
- 首页图片使用合适尺寸与现代格式，并延迟加载非首屏图片；
- 404 页面风格与全站一致，并提供回到首页的入口。

## 十五、最后的判断标准

如果在执行中遇到任何拿不准的取舍，请用下面三个问题来判断：第一，这个改动是否让考研学生更快找到要复习的内容？第二，这个改动是否让页面更安静、更整齐、更像一个认真做出来的学习工具？第三，这个改动是否保留了网站原本最独特、最有价值的东西，也就是把抽象的计算机知识变成看得见、摸得着、能一步一步拆开的过程？三个问题都回答“是”，就去做；有一个回答“否”，就换一种更克制的做法。宁可少做一个装饰，也不要多加一个干扰；宁可多花时间把间距、对齐和字号调准，也不要用新的特效去掩盖排版的问题。实用是骨架，好看是皮肤，二者都要，但骨架先行。

## 十六、补充问题：整机拆解页手机端控件重叠（站长实机反馈）

站长在安卓手机浏览器上打开 /pc，反馈“手机端这里看不到，上面重叠的”。实机截图显示三处问题，必须修复并作为验收项：

1. 顶部控件压住标题：“数据旅程”“展示 / 氛围灯”“全部连线”“重置视角”“408 考点”这一组按钮从右上角向左换行，盖住了左上角的“整机拆解”标题，标题只露出一个“整”字。
2. 提示文字被遮挡：“点一下任意部件，把它从机箱里拆出来看”这行说明被“拆开看”滑杆和第二行按钮压住，读不完整。
3. 底部部件条被截断：“CPU 与散热器 / 内存条 / 显卡 / NVMe 固态硬盘”这一排按钮只露出上半截，原因是手机上顶部导航折成两行，页面高度却按单行导航计算，整页向下溢出，底部被浏览器手势栏挡住。

修复要求：
- 页面高度不能用写死的导航高度去减，改为整页弹性布局：外层占满可视高度（优先使用动态视口高度），导航按实际高度排布，3D 舞台吃满剩余空间。
- 窄屏（宽度小于 700px）下控件按行排开、互不覆盖：第一行标题与一句说明（说明单行省略号）；第二行工具按钮横向滚动，不换行；第三行“拆开看”滑杆；灯效面板在其下方。
- 底部部件条、数据旅程卡片、拆解进度都要加上安全区内边距，不被手势栏或浏览器工具栏遮挡。
- 模型本身保持在中间区域可见，任何控件不得遮挡标题、说明文字和底部按钮。
- 验收：在 360×780、390×844、412×915 三种手机尺寸下截图检查，标题完整、说明完整、底部按钮完整可点，无元素相互重叠；平板和桌面布局不受影响。
