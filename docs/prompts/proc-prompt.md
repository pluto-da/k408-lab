# 408 实验室 · 新增「过程图解」模块执行 Prompt

## 一、站长原话与需求定位

站长原话：

> 再增加基本逻辑电路，加法器和译码器，带 TLB 虚拟存储器的 CPU 访问过程，具有 TLB 和 Cache 存储系统的地址转换过程，单重中断和多重中断服务流程，DMA 传送数据，二级页表的地址转换过程，混合索引分配过程，操作系统的引导过程，设备分配过程，微程序控制器的数据流，指令周期的数据流，进程状态的相互转换，系统调用执行过程，等等。

站点是考研 408 学习站（http://154.8.183.93），实验室页 `/lab` 现在有“章节考点 + 11 个动画实验（排序、二叉树、Dijkstra、Cache 映射、流水线、调度甘特图、页面置换、银行家、TCP 拥塞、子网、三次握手）+ 立体结构图 + 跨科连线”。站长列的这一串，几乎全是计算机组成原理和操作系统里**“画流程图 / 写数据通路 / 算地址”的综合大题高频点**：指令周期数据流和微程序控制器是组成原理 CPU 章的必考图；TLB + Cache 地址转换几乎每两三年出一道 41–47 的综合题；二级页表、混合索引是操作系统综合题的计算主力；中断、DMA、系统调用、设备分配、引导、进程状态是选择题和简答题的高频概念题。

所以这次要做的不是“再加几个科普动画”，而是：**把课本上最难看懂、最需要在脑子里“跑一遍”的十几张流程图，做成可以一步一步点着走、看得见数据在哪个部件之间流动、每一步都写清楚“这一步做了什么、为什么、考试怎么考”的交互图解。**站长的“等等”意味着清单开放，应当在同一个框架里顺手补上同一类、同样高频的过程（例如进程切换），框架要做到以后再加一个流程只需写一段数据。

## 二、深度剖析：站长真正要什么

1. **“看得见数据怎么走”。** 课本上的数据通路图是静态的，箭头一大堆，学生最大的困难是不知道先走哪根线、后走哪根线、每根线上走的是什么（地址？数据？控制信号？）。所以每一步必须：高亮这一步涉及的部件；在连线上跑一个“数据小球”，从源部件流到目的部件；连线上标出传的是什么（如 `(PC)→MAR`、`M(MAR)→MDR`）；寄存器框里实时显示当前值。
2. **“能停能退”。** 复习时要反复对照课本，所以必须能单步前进、单步后退、点步骤列表直接跳到任一步、自动播放可调速，键盘左右键也能用。
3. **“每一步都有考点解释”。** 每一步下方写两层文字：一层是“这一步发生了什么”（用课本上的规范写法，如微操作表达式），一层是“考点 / 易错点”（比如“取指周期最后 (PC)+1→PC 可以和 M(MAR)→MDR 并行”“中断隐指令是硬件完成的，不是一条真正的指令”“多重中断要在保护现场之后才开中断”）。
4. **“计算类要能自己换数字”。** 二级页表、TLB + Cache、混合索引、译码片选这几类，考试是给一个地址让你算。所以这些图解必须带输入框：自己输入虚拟地址 / 文件内偏移 / 主存地址，图解按你的数字重新算出每个字段、每次查表、每次访存，并统计访存次数 / 磁盘访问次数。还要能选择“命中 / 缺失 / 缺页”等不同分支，因为考试经常问“最好情况访存几次、最坏情况几次”。
5. **“电路要能拨开关”。** 基本逻辑门、加法器、译码器不是流程而是电路，最好的学习方式是自己拨输入开关，看输出和每根导线的 0/1 变化，同时看真值表里当前是哪一行。加法器要覆盖 408 最爱考的“补码加减运算器 + 标志位 OF/SF/ZF/CF”，并能逐位看串行进位怎么一级一级传上去。译码器要覆盖 74LS138 的使能端和“用高位地址译码做片选”的存储器扩展题。
6. **手机也能用。** 站长主要在安卓手机上看站（上次截图就是手机）。流程图在窄屏不能缩成看不清的小字：图解区域在窄屏保持可读字号、允许横向滑动，并在每一步自动把高亮部件滚到可视范围；文字解释和步骤列表在图下方完整显示；按钮足够大，可单手点。

## 三、范围：十六个图解，分三类

### 第一类：电路（拨开关交互）

1. **基本逻辑门**：与、或、非、与非、或非、异或、同或七种门同屏，共享输入 A、B 两个开关；每个门用标准门电路符号绘制，导线按 0/1 着色（1 为亮色、0 为灰色）；右侧真值表七列同时显示，当前输入组合所在行高亮。考点：与非门、或非门的功能完备性；异或用于加法器和奇偶校验。
2. **加法器**，三个模式：
   - 半加器：S = A⊕B，C = AB，门级电路，导线 0/1 着色；
   - 一位全加器：S = A⊕B⊕Cin，Cout = AB + (A⊕B)Cin，两个异或、两个与、一个或，门级；
   - 4 位补码加减运算器：输入 A、B 两个 4 位数（点每一位翻转）、减法控制 Sub；B 的每一位与 Sub 异或，Sub 同时作为最低位进位；四个全加器串联；单步模式逐位显示进位如何从 C0 传到 C4；输出和、并实时给出 OF = C4⊕C3、SF = 最高位、ZF、CF = C4⊕Sub，并把 A、B、结果的有符号值和无符号值都显示出来。考点：串行进位延迟随位数线性增长，先行进位把进位表达式展开并行求；溢出判断三种方法。
3. **3-8 译码器（74LS138）**，两个模式：
   - 芯片功能：输入 C、B、A 三个开关和使能端 G1、/G2A、/G2B；输出 /Y0–/Y7 低电平有效；使能不满足时全部输出 1；功能表当前行高亮；
   - 片选译码：CPU 16 位地址，A15–A13 接 138 的 C、B、A，8 片 8KB 存储芯片；输入一个十六进制地址，显示被选中的芯片、片内地址、每片的地址范围表。考点：片选、线选法与译码法的区别，地址范围计算。

### 第二类：流程 / 数据通路（单步动画）

4. **指令周期的数据流**：经典单总线 CPU + 主存结构（PC、MAR、MDR、IR、CU、ACC/ALU、地址总线、数据总线、控制总线、主存），四个模式：取指周期、间址周期、执行周期（以 `ADD @X`，即间接寻址的加法为例）、中断周期。每一步写出规范微操作，如 `(PC)→MAR`、`1→R`、`M(MAR)→MDR`、`(MDR)→IR`、`OP(IR)→CU`、`(PC)+1→PC`；中断周期写出 `(SP)-1→SP, (SP)→MAR`、`1→W`、`(PC)→MDR`、`MDR→M(MAR)`、`向量地址→PC`、`0→EINT`。
5. **微程序控制器的数据流**：IR（操作码）、微地址形成部件、CMAR、地址译码、控制存储器 CM、CMDR（微操作控制字段 | 顺序控制字段）、顺序逻辑（条件标志）、发往执行部件的控制信号。流程覆盖：取指微程序从控存公共入口开始，读出微指令到 CMDR，控制字段发出微命令，下址字段形成下一条微地址；取指结束后由操作码经微地址形成部件映射到该指令的执行微程序入口；执行完成后回到取指公共入口。讲清“一条机器指令 ↔ 一段微程序 ↔ 若干条微指令 ↔ 每条含若干微命令”，水平型 / 垂直型微指令，直接编码 / 字段直接编码，下址字段法 / 计数器法。
6. **带 TLB 的虚拟存储器 CPU 访存过程**（流程图）：CPU 给出虚拟地址 → 查 TLB → 命中则直接得物理地址 → 访问 Cache / 主存；TLB 缺失 → 访问主存中的页表 → 有效位为 1 则得到页框号并更新 TLB；有效位为 0 → 缺页异常 → 操作系统缺页处理程序（找空闲页框或置换、必要时写回脏页、从外存调入、更新页表）→ 返回后重新执行引起缺页的指令。三个模式：TLB 命中、TLB 缺失页表命中、缺页，每个模式都统计访存次数。
7. **具有 TLB 和 Cache 的地址转换过程**（可输入）：参数采用一道标准题：虚拟地址 32 位、页大小 4KB、物理地址 24 位；TLB 4 路组相联共 8 组（TLB 组号 3 位、标记 17 位）；Cache 8KB、2 路组相联、块大小 32B（组号 7 位、块内地址 5 位、Cache 标记 12 位）。用户输入虚拟地址并选择“TLB 命中 / TLB 缺失”和“Cache 命中 / Cache 缺失”，图解依次展示：虚拟地址拆成虚页号 | 页内偏移；虚页号再拆成 TLB 标记 | TLB 组号；选中 TLB 某组、4 个标记并行比较；得到页框号；拼成物理地址；物理地址拆成 Cache 标记 | 组号 | 块内地址；选中 Cache 某组、2 个标记比较；命中读出、缺失则从主存调块。每个字段都标出位数和十六进制值。考点：页内偏移 12 位恰好覆盖 Cache 组号 + 块内地址，所以可以“虚拟索引、物理标记”并行查 TLB 和 Cache。
8. **单重中断与多重中断服务流程**，两个模式并列对照：单重中断：中断隐指令（关中断、保存断点、取中断服务程序入口）→ 保护现场 → 设备服务 → 恢复现场 → 开中断 → 中断返回；多重中断：中断隐指令 → 保护现场和屏蔽字 → 开中断 → 设备服务（此时可被更高优先级中断打断）→ 关中断 → 恢复现场和屏蔽字 → 开中断 → 中断返回。考点：两者区别仅在“开中断”的位置；中断隐指令由硬件完成；屏蔽字改变处理优先级。
9. **DMA 传送数据**：三个阶段：预处理（CPU 用程序向 DMA 控制器写入主存起始地址 AR、传送字数 WC、设备地址、传送方向，启动设备）；数据传送（设备数据就绪→进入 DMA 数据缓冲 DR→DMA 向 CPU 发总线请求 HRQ→CPU 在当前机器周期结束后让出总线并回 HLDA→AR 送地址总线、DR 送数据总线写主存→AR+1、WC−1→若 WC≠0 继续下一个字）；后处理（WC=0 时 DMA 向 CPU 发中断请求，CPU 执行中断服务程序做校验、决定是否继续）。考点：DMA 请求在机器周期结束时响应，中断请求在指令周期结束时响应；停止 CPU 访存、周期挪用、交替访存三种方式。

### 第三类：操作系统流程与计算

10. **二级页表的地址转换过程**（可输入）：32 位虚拟地址、页大小 4KB、页表项 4B，所以拆成 10 位页目录号 | 10 位页表索引 | 12 位页内偏移；页目录基址寄存器 PDBR；输入虚拟地址，图解展示第一次访存读页目录项、第二次访存读页表项、拼出物理地址、第三次访存取数据；可切换“页表项有效 / 缺页”。考点：没有 TLB 时一次访存变三次；页表项地址 = 基址 + 索引 × 页表项大小；一页恰好放下一张页表（1024 × 4B = 4KB）。
11. **混合索引分配过程**（可输入）：索引结点中 10 个直接地址、1 个一次间接、1 个二次间接、1 个三次间接；块大小可选 1KB / 4KB；地址项 4B；输入文件内字节偏移，图解算出逻辑块号、块内偏移、落在哪一级、各级索引块里取第几项，逐步展示每一次读磁盘，统计读盘次数（假设索引结点已在内存）；同时给出每一级能表示的块号范围和最大文件长度。
12. **操作系统的引导过程**：加电 → CPU 从固定地址执行主板 ROM 中的 BIOS → 硬件自检 POST → 按启动顺序找到引导设备，读入磁盘 0 号扇区主引导记录 MBR（引导程序 + 分区表）→ 扫描分区表找活动分区 → 读入活动分区的引导扇区 PBR → 执行分区引导程序，加载启动管理程序 → 加载操作系统内核到内存 → 内核初始化（建立中断向量、页表、各类数据结构）→ 创建第一个用户进程 / 启动 shell。考点：引导程序在 ROM 中自举装入；MBR 在磁盘第一个扇区；UEFI + GPT 是现代替代方案。
13. **设备分配过程**：进程以逻辑设备名申请 → 查逻辑设备表 LUT 得物理设备 → 查系统设备表 SDT 找到该设备的设备控制表 DCT → 设备忙则进入设备等待队列 → 分配设备 → 由 DCT 找到控制器控制表 COCT → 控制器忙则进入控制器等待队列 → 分配控制器 → 由 COCT 找到通道控制表 CHCT → 通道忙则等待 → 分配通道 → 设备、控制器、通道都分配成功才能启动 I/O。两个模式：全部空闲 / 控制器忙需等待。考点：四张表的层次关系，设备独立性。
14. **进程状态的相互转换**：五状态模型（创建、就绪、运行、阻塞、终止）与七状态模型（增加就绪挂起、阻塞挂起）。用一个进程的“生命故事”逐步演示每一条转换和触发事件（创建完成、被调度、时间片到 / 被抢占、请求 I/O 或 wait、I/O 完成或被唤醒、运行结束；挂起与激活）。考点：就绪↛阻塞、阻塞↛运行；运行→阻塞是主动行为，阻塞→就绪是被动行为。
15. **系统调用执行过程**：用户程序准备参数（放寄存器 / 栈）→ 执行陷入指令（trap / int 0x80 / syscall）→ CPU 由用户态切到核心态，硬件保存 PC、PSW → 按中断向量进入系统调用总入口 → 按系统调用号查系统调用表 → 执行对应内核服务例程 → 返回值放寄存器 → 恢复现场，切回用户态 → 返回用户程序继续执行。考点：陷入指令在用户态执行；它属于内中断（自愿中断）；系统调用与库函数的区别。
16. **进程切换过程**（“等等”中补充）：时钟中断或系统调用进入内核 → 保存当前进程上下文（PC、PSW、通用寄存器）到它的 PCB → 修改其 PCB 状态并移入相应队列 → 调度程序选择新进程 → 修改新进程 PCB 状态为运行 → 更新内存管理数据结构（切换页表基址、刷新 TLB）→ 恢复新进程上下文 → 返回用户态运行新进程。考点：调度与切换的区别，切换开销来源。

## 四、交互规格

- **位置**：`/lab` 页新增一节“过程图解”（锚点 `#proc`），位于“动画实验”之后、“立体结构图”之前；左侧目录和顶部搜索都能找到；支持 `/lab#proc-tlbcache` 这类链接直达某个图解。
- **选择器**：按“组成原理 / 操作系统”两组列出十六个图解，标签带科目色点；横向可滑动，键盘左右键可切换。
- **每个图解统一布局**：标题行（名称、科目）、模式按钮（如取指 / 间址 / 执行 / 中断）、输入区（地址、分支选择）、图解画布、控制条（上一步、播放 / 暂停、下一步、重置、速度）、当前步骤卡片（第几步 / 共几步、标题、说明、考点）、关键量面板（寄存器值、访存次数、读盘次数、拆出的字段等）、完整步骤列表（可点击跳转）、右侧“考点”笔记。
- **画布元素**：普通部件为圆角框，带名称和数值；寄存器为等宽字体显示数值；判断为菱形；起止为胶囊形；表格节点（页目录、页表、TLB 组、Cache 组、索引块、SDT/DCT 等）显示几行内容并高亮被选中的那行；地址字段节点按位宽画成分段条并标出位数和值。当前步骤的部件描边加粗并着科目色，已走过的部件浅色标记，未走到的保持中性。连线上方标注传送内容；当前步骤的连线加粗并有一个数据小球从起点流到终点（减少动态效果的系统设置下不播放小球动画）。
- **窄屏**：画布最小宽度保证字号可读，容器横向滚动；每一步自动把当前部件滚到可视区域；步骤卡片和列表在下方。
- **可访问性**：画布有 aria-label 概述当前步骤；步骤卡片 aria-live；所有控件可键盘操作，有焦点样式。

## 五、实现方案

沿用实验室现有的“遗留模块”架构（`public/legacy/` 下原生 JS + `window.X` 辅助函数），新增：

1. `public/legacy/js/11-proc.js`：一个通用图解引擎 + 十六个图解的数据。流程类图解用声明式数据描述：`nodes`（id、坐标、尺寸、种类、名称、初始值）、`edges`（起止部件与连接边、标签）、`steps`（标题、说明、考点、当前高亮部件、要跑小球的连线、对部件数值的修改、关键量的修改）。计算类图解在用户输入后由函数生成同样结构的数据。电路类图解单独用一个小型门电路求值器渲染，导线按 0/1 着色。
2. `public/legacy/css/legacy-04.css`：新模块样式，沿用实验室已有的配色变量、按钮样式、圆角和字体。
3. `body.html`：新增 `#proc` 小节和目录项；`manifest.json` 注册新脚本和样式；`pages/Lab.tsx` 的锚点跳转支持 `#proc-<id>`；搜索索引加入十六个图解名称。
4. 所有地址计算用整数位运算，并为二级页表、TLB + Cache、混合索引、片选写单元测试，确保字段拆分、查表、计数在边界值（0、最大值、跨级边界）上都正确。

## 六、验收标准

1. 十六个图解都能打开，每个模式从第一步走到最后一步、再退回第一步，没有报错，步骤数与说明对应。
2. 二级页表：输入 `0x00403A7C` 得到页目录号 1、页表索引 3、偏移 `0xA7C`；访存次数 3；缺页模式给出缺页处理流程。
3. TLB + Cache：输入任意地址，字段位数为 17/3/12 与 12/7/5，物理地址低 12 位等于虚拟地址低 12 位；四种分支组合都能走通。
4. 混合索引：块 1KB 时偏移 0 落在直接块 0，偏移 10240 落在一次间接第 0 项，偏移 10240 + 256×1024 落在二次间接；读盘次数分别为 1、2、3。
5. 加减运算器：A=0111、B=0001、加法得 1000 且 OF=1、SF=1；A=0011、B=0011、减法得 0000 且 ZF=1、CF=0。
6. 138 译码器：使能不满足时输出全为 1；片选地址 `0x6000` 选中第 3 片（Y3）。
7. 手机 390×844 视口下，画布可读、可横向滑动、当前部件自动可见，没有内容溢出页面。
8. 工程检查（类型检查、lint、单元测试、构建）全部通过；部署后 `/`、`/lab`、`/pc`、`/api/health` 返回 200；线上对几个图解再走一遍。

## 七、不要做的事

- 不要用视频或 GIF，必须是可单步、可回退、可改数字的真交互。
- 不要只画框和箭头不写内容，每一步都要有规范表述和考点。

- 不要编造“标准答案”之外的非常规术语，统一采用王道 / 唐朔飞 / 汤小丹教材中通行的写法。

## 八、内容质量标准（每一步怎么写）

每一步的文字都按“三句话”原则写：第一句用教材规范表达式说清这一步的动作（谁、送到哪、传的是什么），第二句解释这一步为什么必须在这里发生（它依赖上一步的哪个结果，又为下一步准备了什么），第三句（如有）写考点或易错点，用“考点：”开头单独成段，便于考前快速扫读。数值一律同时给出十进制和十六进制，位数一律写明“几位”，例如“虚页号 20 位 = 0x00403”。所有统计量（访存次数、读盘次数、门延迟级数）在关键量面板里随步骤累加，最后一步给出总数和“最好 / 最坏情况”的对比，正好对应综合题常见的追问。

流程图的版式统一为“从左到右、从上到下”的阅读顺序：CPU 在左、主存和外设在右；判断菱形“是”向下、“否”向右；起点和终点用胶囊形。颜色只用两层：科目色表示“正在发生”，浅灰表示“已经走过”，其余保持中性，避免一屏五颜六色分散注意力。每个图解的右侧笔记只放三到五条最值得背的结论，不重复步骤里的内容。
