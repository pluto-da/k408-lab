# 整机拆解 · 「化身数据」第一人称游走与模拟 · 执行 Prompt

## 一、站长原话

> 再增加一个化为类似数据一样的第一人称视角，在电脑里进行游走，并模拟。

## 二、深度剖析：站长真正要什么

### 1. 现状

整机拆解页 `/pc` 已经有一台可以旋转、拆开的 3D 电脑，九个部件（CPU 与散热器、内存条、NVMe 固态硬盘、机械硬盘、显卡、网卡、电源、主板与总线、机箱与风道），部件之间有总线连线（内存总线、PCIe、DMI、SATA、供电线）。还有一个“数据旅程”：七站自动播放，一个发光小球沿着锚点从网卡经 DMA 写入内存，再到 CPU、Cache、显卡、硬盘，镜头在外面远远跟拍，配一行字幕和考点标签。

这个旅程是“第三人称看小球”：学生是旁观者，镜头在机箱外，小球很小，路径是预设好的，学生不能参与，看完也就记住一个大概。

### 2. 站长想要的变化

站长说“化为类似数据一样的第一人称视角”，关键词有三个：

- **化为数据**：学生不再是旁观者，而是“变成”那一段数据本身。镜头就是数据的眼睛，缩小到芯片尺度，沿着总线穿行，钻进内存条、Cache、CPU 的内部。这种代入感是学习体验的核心——“我就是那个地址”“我正在被搬进 Cache”。
- **在电脑里游走**：不是坐过山车式地被动播放，而是可以在电脑里“走”：有自动巡航，也能自己控制前进、停下、回头看、在岔路口选方向（例如 Cache 命中走近路、缺失要去内存走远路）。
- **并模拟**：路上发生的事情要真实模拟 408 考点里的机制，而不是只放字幕：地址怎么被拆成标记、组号、块内地址；TLB 查没查到；页表怎么一级一级查；Cache 哪一行被替换；DMA 一次搬多少字节；中断怎么保存现场；流水线里五个阶段怎样重叠；网卡收到的帧怎么校验。学生能改参数（地址、Cache 组相联路数、替换策略、是否命中），看到路线和结果随之变化。

一句话：把 408 组成原理、操作系统、计算机网络中“数据在计算机里怎么走”的知识，变成一个可以亲身走一遍、可以动手改参数的第一人称模拟。

### 3. 为什么值得做

408 中最难理解、最容易考错的，恰恰是这些“看不见的过程”：一条访存指令从虚拟地址到拿到数据，要经过 TLB、页表、Cache、主存，可能还要缺页中断、从磁盘调页；一次网络收包要经过网卡、DMA、中断、协议栈、用户进程。书上是一张张静态框图，学生很难把它们串成一个完整的故事。第一人称的“化身数据”恰好把这些串在同一条路线上，而且和站内已有的动画实验（Cache 映射、页面置换、TLB、DMA、中断、流水线、CRC 等）一一对应，学生在游走中看到某个机制，可以一键跳到对应实验深入练习。

### 4. 必须遵守的既有要求

- 网站上不出现所用技术的说明，只放学习内容。
- 风格实用、克制，功能优先；第一人称场景要有质感，但不堆砌炫技特效。
- 所有讲解文字原创，依据官方考纲，不出现任何辅导书痕迹。
- 手机、平板、电脑都要能用（刚完成多设备适配，不能倒退）。

## 三、体验设计

### 1. 入口
- `/pc` 页面工具栏现有“数据旅程”按钮旁边，新增“化身数据”按钮；首页“常用实验”和实验室相关实验（Cache、TLB、DMA、中断、流水线）中也放入口链接，支持 `/pc?ride=<路线 id>` 直达某条路线。
- 点击后先出现路线选择面板（见第四节），选好后镜头从机箱外快速缩小、俯冲到起点，画面上出现“你现在是一段数据”的提示，进入第一人称。

### 2. 第一人称画面构成
- **主画面**：镜头位于数据所在位置，朝前进方向。总线表现为一条发光的通道（隧道感），两侧可见主板走线、芯片封装的轮廓；进入部件时切换到该部件的“内部场景”（见第五节）。
- **自身形象**：画面下方有一圈半透明的“数据外壳”，显示自己携带的内容：例如“虚拟地址 0x0040 2A7C”或“以太网帧 · 1514 字节”或“指令 LOAD R1, [R2+8]”，随着处理过程实时变化（地址被拆分、翻译成物理地址、数据被取回）。
- **抬头信息（HUD）**：左上为当前位置（例如“主板 · 内存总线 DDR5”）、已用时间（以时钟周期或纳秒计）；右上为小地图（整台电脑的简化俯视图，标出自己的位置和走过的路径）；底部为当前步骤的讲解字幕和考点标签。
- **岔路口**：到达需要判断的地方（TLB、Cache、页表、缺页），画面前方出现两三个分叉通道，每个通道上写着条件（“TLB 命中 → 直接得到物理地址”“TLB 缺失 → 去内存查页表”）。模拟会根据当前参数自动决定走哪条，并高亮；学生也可以切到“我来判断”模式，自己选一条，选错时会提示原因（这就是边玩边学的闯关感）。

### 3. 操作方式
- **自动巡航**（默认）：按讲解节奏前进，到关键点自动减速并停下讲解，点“继续”前进。
- **手动游走**：电脑上按住鼠标拖动转头，W / S 或方向键前进后退，空格暂停，Q / E 加减速；手机和平板上单指拖动转头，屏幕右下角有前进 / 后退的按钮，双指捏合调整速度。手动模式下镜头仍约束在通道内，不会“走丢”。
- **时间轴**：底部有一条进度条，标出所有站点，点击可以跳到任意站点，可以回看。
- **视角切换**：随时按 V 或点按钮切换“第一人称 / 跟随视角 / 整机全景”，全景中能看到自己是一个光点在整台电脑的哪一处，回到第一人称后继续。
- **退出**：Esc 或“退出”按钮，镜头拉回到机箱外的总览。

### 4. 结算
- 路线结束后出现一张“旅程小结”卡：总耗时（周期数或纳秒）、经过的部件、命中与缺失次数、访存次数、关键数字（例如有效访问时间的计算式代入本次数值），以及本次涉及的考点列表，每个考点链接到实验室中对应的实验或性质卡片。
- 提示“换个参数再走一遍”：例如把 TLB 改成缺失、把 Cache 改成直接映射，再走一次对比耗时。

## 四、路线（场景）设计

至少实现以下六条路线，每条 6 ~ 12 个站点，均以现有 3D 电脑的部件和锚点为骨架：

### 路线一：一次访存——从虚拟地址到数据（核心路线）
起点：CPU 内部，一条 LOAD 指令进入执行阶段，产生虚拟地址。
站点：地址拆分（虚页号 + 页内偏移）→ TLB 查找（命中 / 缺失岔路）→ 缺失时沿内存总线到内存查页表（可选一级 / 二级页表，逐级查找，显示页目录号、页表索引）→ 若页不在内存则触发缺页中断，转向路线五的磁盘调页支线 → 得到物理地址 → 物理地址拆分为 Cache 的标记、组号、块内地址 → 在 L1 对应组中比较标记（命中 / 缺失）→ 缺失时逐级到 L2、L3，再到内存按块调入，演示替换哪一行（LRU / FIFO / 随机）→ 数据回到寄存器。
可调参数：虚拟地址、页大小、TLB 是否命中、页表级数、Cache 容量、块大小、相联度、替换策略、各级访问时间。
结算：本次访问时间 = 各段时间之和，并给出有效访问时间公式的代入式。
关联：TLB 实验、Cache 地址映射实验、页面置换实验、多级页表性质、EAT 性质。

### 路线二：网卡收到一个网页数据包
起点：网线进入网卡的 RJ45 接口，自己是一帧以太网帧。
站点：物理层比特到达（显示编码方式）→ 网卡检查目的 MAC 和 CRC（演示校验通过或失败丢弃的岔路）→ DMA 经 PCIe、芯片组、内存控制器写入内存的接收缓冲区（显示一次搬运的字节数）→ DMA 结束发出中断 → CPU 响应中断、保存现场、执行中断服务程序 → 协议栈逐层拆封：去掉以太网首部、检查 IP 首部（目的地址、TTL、分片）、TCP 首部（端口、序号、确认号）→ 数据交给浏览器进程的套接字缓冲区 → 进程被唤醒。
可调参数：帧长、是否 CRC 出错、是否需要 IP 分片、TCP 是否乱序。
关联：CRC 实验、DMA 与中断图解、IP 分片实验、封装与解封装图解、TCP 相关实验。

### 路线三：按下键盘，字母出现在屏幕上
站点：键盘控制器产生扫描码 → USB 经芯片组 → 中断 → 键盘驱动把扫描码转为字符放入缓冲区 → 应用程序的系统调用从用户态陷入内核态读取 → 字符写入显存（经 PCIe 到显卡）→ 显卡扫描输出到屏幕。
关联：中断图解、程序查询 / 中断 / DMA 比较、用户态与内核态。

### 路线四：一条指令的流水线之旅
在 CPU 内部场景中进行：取指（从 L1 指令 Cache）→ 译码 → 执行 → 访存 → 写回五个阶段，像五节车厢的站台；同时有多条指令在不同站台，可以演示数据相关导致的停顿（气泡）与转发、分支预测失败导致的冲刷。
可调参数：指令序列（预设几组）、是否开启转发、分支是否预测正确。
关联：指令流水线实验、CPU 性能与 Amdahl 性质。

### 路线五：从硬盘读一个文件
站点：进程调用 read → 文件系统根据目录项和索引结点找到数据块号（演示混合索引的直接块、一级间接块）→ 若数据不在页缓存则发起磁盘请求 → 沿 SATA 到机械硬盘（演示寻道、旋转延迟、传输）或沿 PCIe 到固态硬盘（演示 NAND 页读取）→ DMA 回内存 → 中断 → 数据拷贝到用户缓冲区。
可调参数：文件偏移（决定走直接块还是间接块）、选择机械硬盘或固态硬盘、磁盘调度策略。
关联：混合索引性质、磁盘调度实验、文件打开读取图解。

### 路线六：开机——电源到第一条指令
站点：电源输出 +12V / +5V / +3.3V → 主板供电、CPU 供电 → CPU 复位，从固定地址取第一条指令（固件）→ 自检、初始化内存 → 从硬盘加载引导程序 → 加载操作系统内核。
关联：计算机系统概述、操作系统引导。

## 五、部件内部场景

进入部件时，镜头穿过封装外壳，进入一个抽象而清晰的“内部世界”，不追求真实芯片显微结构，而追求“把考点画清楚”：

- **CPU 内部**：寄存器组像一排带编号的格子，ALU 是中央的运算台，控制器发出控制信号线；L1 / L2 / L3 Cache 是由近到远的三层“仓库”。
- **Cache 内部**：按组排列的行，每行显示有效位、脏位、标记和数据块；当前组高亮，比较标记时逐行亮起；替换时被替换的行翻转淡出、新块飞入。
- **TLB 与页表**：TLB 是一小排快表格子；页表在内存中表现为一排排表项，多级页表是“目录 → 表 → 页框”的楼层结构，数据乘坐电梯逐层下降。
- **内存条内部**：存储芯片的行列阵列，访问时行地址、列地址依次点亮；多体交叉时多个芯片轮流亮起。
- **硬盘内部**：机械硬盘的盘片和磁头，演示寻道（磁头移动）、旋转等待（扇区转到磁头下）、读取；固态硬盘的 NAND 块与页。
- **显卡内部**：显存中的帧缓冲区，像素逐行被扫描输出。
- **网卡内部**：接收队列、校验单元、DMA 引擎。

每个内部场景都是程序化生成的简洁几何体，配色沿用现有部件和总线颜色（内存总线紫色、PCIe 蓝色、DMI 青色、SATA 橙色、网卡绿色、供电黄色），保证学生在“外面”和“里面”看到同一套颜色语言。

## 六、模拟引擎

### 1. 与画面分离的纯逻辑层
- 新建 `src/pc/ride/` 目录：`sim/` 中是纯函数的模拟器（地址拆分、TLB、多级页表、Cache 组相联与替换、DMA、中断、流水线、文件索引、磁盘寻道），输入参数、输出“事件序列”（每个事件包含站点 id、发生的动作、时间开销、数据外壳内容变化、岔路选择）。
- 画面层只按事件序列播放：移动镜头、播放内部场景动画、更新 HUD。这样模拟逻辑可以完全用单元测试覆盖，并保证与实验室中已有实验的计算结果一致（例如同样的 Cache 参数和地址序列，命中情况与 Cache 映射实验相同）。

### 2. 路线数据格式
- 每条路线是一份配置：站点列表（id、所在部件、锚点、内部场景类型、讲解文字、考点标签、关联实验）、岔路定义、默认参数与可调参数范围、使用哪个模拟器。
- 讲解文字中的数值从模拟结果中填入（例如“组号 = 5，在第 5 组的 4 行中比较标记”）。

### 3. 镜头与路径
- 外部路径沿用现有锚点与总线连线，生成平滑曲线，镜头沿曲线移动，朝向为曲线切线方向，加入轻微的惯性与转弯倾斜，增强“在通道里飞行”的感觉；速度在直线段快、在站点前减速。
- 进入部件时用一次短暂的“穿过外壳”过渡（画面缩放 + 淡入内部场景），退出时反向。
- 手动模式下，镜头位置约束在曲线附近，转头角度限制在合理范围；用户放开操作后自动回正。

## 七、多设备与性能

- 手机：内部场景几何体数量控制在低水平，关闭后期效果；HUD 简化为顶部位置条和底部字幕，小地图收为按钮；操作按钮不小于 44 像素；横屏时字幕放在右侧，保留画面高度。
- 平板：完整 HUD，小地图缩小；触控操作。
- 电脑与大屏：完整效果，键盘快捷键，HUD 随根字号放大。
- 资源：内部场景程序化生成，不新增大模型文件；进入第一人称时才初始化相关模块（按需加载），不影响 `/pc` 首屏速度。
- 帧率目标：电脑 60 帧，中端手机不低于 30 帧；低端设备自动降低像素比和效果。
- 减少动态效果：系统开启时，改为“站点到站点”的平滑切换，不做持续飞行动画，并减少镜头晃动。

## 八、可访问性与学习辅助

- 所有讲解同时以文字呈现，可以暂停阅读；字幕可调大小。
- 提供“文字版路线”：一个按站点排列的列表，读屏软件和不便看 3D 的学生可以按列表学习同样的内容。
- 键盘完整可操作，焦点可见。
- 每个站点有“这是什么？”按钮，弹出一张小卡片，解释当前部件和机制，附上关联实验链接。

## 十、验收标准

1. `/pc` 出现“化身数据”入口，六条路线均可从头走到尾，`/pc?ride=<id>` 可直达。
2. 路线一在不同参数下（TLB 命中 / 缺失、页表一级 / 二级、Cache 命中 / 缺失、不同相联度和替换策略）走出不同路径，时间开销计算正确，与实验室对应实验结果一致，并有单元测试覆盖。
3. 第一人称画面中数据外壳内容随处理过程实时变化；HUD、小地图、时间轴工作正常；岔路口在“我来判断”模式下能判对错并解释。
4. 自动巡航、手动游走、视角切换、暂停回看、退出均可用；电脑键盘与手机触控都能完整操作。
5. 在 393、852 × 393、820 × 1180、1210 × 800、1366 × 768、1920 视口下无溢出、无报错，HUD 不遮挡关键画面；中端手机帧率不低于 30。
6. 结算卡数据正确，考点链接跳转到正确的实验或性质。
7. 全部讲解原创，来源扫描为零；页面上不出现技术说明。
8. 全部单元测试、类型检查、lint、构建通过；部署后线上可用。

## 十一、风险与取舍

- 六条路线工作量大，按“路线一做到最好 → 路线二、四 → 路线三、五、六”的顺序推进，每完成一批就上线，让站长尽早体验并反馈。
- 第一人称在手机上容易晕：镜头运动要平稳，转弯倾斜幅度小，提供“减少晃动”开关。
- 模拟的精确度与画面节奏之间要取舍：时间按比例展示（标注真实数量级，例如 Cache 约 1 纳秒、内存约 100 纳秒、机械硬盘约 10 毫秒），避免等待过长；在 HUD 上用“真实时间”和“演示时间”两种读数说明差异，这本身也是一个重要的学习点：存储层次之间速度相差几个数量级。
- 与现有“数据旅程”的关系：保留旧旅程作为“快速概览”，新模式作为深入体验，两者入口并列，避免重复建设；旧旅程的站点数据可以复用为路线二的骨架。

## 十二、一次完整体验的示例（路线一，默认参数）

学生点“化身数据”，选“一次访存”。画面从机箱外俯冲进 CPU，提示“你是一条 LOAD 指令产生的虚拟地址 0x0040 2A7C”。数据外壳上地址分裂成两段：虚页号 0x00402、页内偏移 0xA7C（页大小 4 KB）。前方是 TLB 小格子，逐格比较，没有找到，前方通道分叉，“TLB 缺失”一路亮起。学生沿内存总线飞向内存条，进入页表楼层，先查页目录第 1 项，再查页表第 2 项，取得页框号 0x1F3。外壳上的地址变成物理地址 0x1F3A7C，又分裂成标记、组号、块内地址三段。飞回 CPU 进入 L1（32 KB、4 路组相联、块大小 64 B，共 128 组），第 105 组的四行逐一比较标记，未命中；去 L2，命中，整块数据被搬到 L1，按 LRU 替换掉最久未用的一行。数据最终落入寄存器 R1。结算卡显示：本次共访存 2 次（页表两级）、TLB 缺失、L1 缺失、L2 命中，总耗时 2 × 100 + 1 + 10 = 211 纳秒，并提示“把 TLB 设为命中再试一次，看看能省多少时间”。

## 十三、数值与口径约定

- 默认时间参数：寄存器与 L1 约 1 纳秒，L2 约 4 纳秒，L3 约 12 纳秒，主存约 100 纳秒，固态硬盘约 100 微秒，机械硬盘约 10 毫秒，TLB 约 1 纳秒；在参数面板中可调整，并注明“题目给出的数值以题目为准”。
- 有效访问时间的计算区分“同时访问”和“先查 Cache 再访存”两种口径，与站内性质卡片保持一致。
- 页表项大小、页大小、地址位数等默认值与站内实验一致，学生在两处看到的数字相同。
