# 化身数据 · 界面设计精修（v19）· 执行 Prompt

## 一、站长原话与范围判断

> 能把 UI 设计的更好吗？深度剖析研读分析下我想要的，写出不少于 5000 字的高质量 Prompt 发给我，之后按照 Prompt 进行深度研究执行。

这句话紧接在 v18（遮挡修复）之后，站长看到的是 v18 的平板、手机、电脑线上截图。v18 解决了“挡住”，但界面本身仍然粗糙：它像是把一堆控件摆到了不挡画面的位置，而不是一个经过设计的界面。所以这次的范围是 **“化身数据”模式（/pc?ride=access）的整体界面设计**，包括画面四周的全部 HUD、讲解侧栏 / 抽屉、控制条、菜单、结算卡，以及画面内的文字板、标签和场景杂物。网站其他页面（首页、实验室、整机拆解原模式）不在本次范围内，但化身数据进出时与网站顶栏的衔接在范围内。

之前一直遵守“不要整体视觉改版”，那是在修遮挡时的约束。这一次站长明确要求把界面设计做得更好，所以允许重新设计化身数据模式的视觉与版式；但仍然要与网站整体气质一致（克制、实用、学习工具而不是游戏），不堆特效，不改教学内容和模拟逻辑。

## 二、站长真正要什么

站长是一个做考研 408 学习站的开发者，自己也是考生，对画面质量要求高，反复提“深度优化”“高质量”。从历次反馈推断，他要的是：

1. **一眼看上去像成品**：配色统一、层级清楚、间距整齐，没有“临时拼上去”的按钮和孤零零的元素。
2. **学生的注意力只落在该看的地方**：当前讲的对象最亮、最清楚，讲解文字最好读，其余全部退到背景。
3. **操作一目了然**：下一步该点哪里不用想；同一个功能只有一个入口。
4. **在手机、平板、电脑上都好看**，不是“电脑版缩小”。
5. **克制**：不要霓虹、不要发光描边满屏、不要粒子乱飞。高级感来自秩序，而不是特效。

## 三、对 v18 截图的逐项设计诊断

以下问题来自 v18 线上截图（平板横屏 1210×680、手机竖屏 393×732、手机横屏 852×273、电脑 1366×640）和 v18 功能截图。

### A. 整体结构
1. **网站白色顶栏与深色化身画面割裂**。顶部一条亮白的网站导航（考研408、实验室、整机拆解、登录、注册）压在深色沉浸画面上方，对比极强，视线先被它吸走，而且占了 56 像素高度。进入化身数据后，它应该退场或变成深色细条。
2. **画面和侧栏之间只有一条细线**，两块颜色几乎一样，侧栏没有明确的“面板”感，也没有和画面形成主次。
3. **左上位置条、右上工具组、底部控制条、侧栏四块各自为政**，圆角、高度、边框、字号都不一致：左上位置条高 32、圆角 8；右上按钮高 40、圆角 8 但“退出”是亮白底；底部按钮高 44，“下一站”是浅蓝实心；侧栏的考点标签又是另一种胶囊。

### B. 按钮与操作
4. **“退出”按钮是亮白底黑字**，在深色界面里是最显眼的元素，等于把“离开”设为主操作，这是反的。
5. **“下一站”出现两次**：侧栏右上角的“›”圆角按钮和底部控制条的“下一站”。重复入口让人犹豫。
6. **“下一站”的浅蓝实心色（约 #8fa8ff）发灰发粉**，不像主按钮，和网站主色 #2f5bea 也不一致。
7. **“第一人称”按钮用文字表示当前视角**，看不出它是切换按钮还是状态显示。
8. **岔路选项**（“命中 → 直接得到页框号”“缺失 → 去主存查页表”）在自动判断模式下一个灰、一个绿描边，看起来像是两个都可以点的按钮，但其实答案已经给出；视觉上“已选中”和“可点击”混在一起。
9. **“这是什么？”“小地图”两个按钮孤零零地挂在侧栏底部**，与上方内容没有关系。
10. **进度条是 11 段细线**，没有站名、没有当前站标记以外的信息，也不能点；“自动巡航”按钮宽而突兀。
11. **手机横屏底部按钮**有“‹”“Ⅱ”“下一站”“巡航”四个，风格不统一（两个图标、一个长按钮、一个文字按钮），“更多”“退出”又跑到侧栏顶部右侧。

### C. 侧栏 / 抽屉内容
12. **侧栏中部大块空白**：电脑上讲解正文和考点标签之后，到岔路问题之前有 120 多像素的空洞，内容上重下轻、头重脚轻。
13. **数据外壳卡片信息密度不均**：三枚彩色胶囊（标记 / 组号 / 偏移）颜色是黄、绿、蓝，各自带描边和底色，像三张贴纸；底下一行灰色小字解释，层级弱。胶囊的颜色与画面里 TLB 表格的颜色毫无关系，学生建立不了对应。
14. **讲解正文行长偏长、行距偏紧**，加粗结论句在一段里，没有被单独强调。电脑侧栏一行约 24 个汉字尚可，但平板只有 19 个汉字时换行很碎。
15. **考点标签**（“快表 TLB”“TLB 缺失”“+1 ns”）样式与按钮太像，看起来能点但其实是链接还是标签不清楚；“+1 ns”是本站耗时，和考点混在一起。
16. **站号“2/11”用浅灰小字**，几乎看不见；站名字号和正文差距不够。

### D. 画面内
17. **文字板配色**：TLB 和 L1 的行都是暗红棕底 + 红色描边，红色本该表示“缺失 / 错误”，现在成了默认底色；L1 缺失时 4 行全是红框，加上绿色的错位边（z-fighting 残影，截图中每行左右露出绿色细边），显得杂乱。
18. **文字板左侧的“组列表”空白块**（TLB 的 8 个灰色占位块）只有当前组有字，其余空着，像是没加载出来。
19. **场景杂物**：左侧露出半截红色拱门（岔路门洞）、悬空的“缺失 → 去主存查页表”小牌子、右侧悬浮的“回程通道 → 寄存器”标签，与当前站无关却很显眼；L1 站背景里“4 路组相联 · 共 128 组 · 第 105 组”和“标记 0x0F9”的标题被右上工具组压住一半。
20. **场景标签样式**（“MMU · 快表 TLB”）是一枚带紫色左边条的小黑卡，字号 12、与侧栏风格不一致。
21. **画面背景**是近黑色加零散竖线和光点，看不出身在 CPU 内部还是内存里，场景感弱；但又不能靠加特效解决。

### E. 手机
22. 手机竖屏抽屉的“展开”按钮是一个大方块，抢眼；外壳胶囊在一行里挤着，第三枚被截断。
23. 手机横屏侧栏顶部的进度细线、外壳胶囊横向滚动、正文 5 行、按钮一行，信息过多且每样都很小。

## 四、设计方向

一句话：**“深色、安静、有秩序的学习仪表”**。参考的气质是专业工具软件（如示波器软件、代码编辑器的深色主题、航空座舱的信息屏）：背景沉、信息亮、颜色有语义、动效短而准。

### 1. 统一的设计变量（在 ride.css 顶部定义一套 --ride-* 变量，所有元素只用变量）

- 背景层级：画面底 #0b0d12；面板底 #12151c；面板上的卡片 #181c25；悬停 #1f2430；分割线 rgba(255,255,255,0.07)；描边 rgba(255,255,255,0.10)。
- 文字：主文字 #e8eaf0；次文字 #a3a9b7；弱文字 #737a89（在面板底上对比度 ≥ 4.5:1，需实测）。
- 主色：沿用网站 #2f5bea 的同色相，在深色上提亮为 #5b7cff（主按钮底）、#8aa2ff（链接文字）。
- 语义色（全模式统一，画面和面板共用同一套，学生能对应）：
  - 地址字段：标记 = 琥珀 #e0a43a；组号 / 索引 = 青绿 #3fb5a0；偏移 = 天蓝 #5aa9e6；页框号 / 物理地址 = 紫 #9b8cff。
  - 状态：命中 = 绿 #3fbf7f；缺失 = 红 #e5534b；进行中 / 当前 = 主色。
  - 红色只用于“缺失、无效、替换掉”，不再用作默认底色。
- 圆角：小 6、中 10、大 14；按钮统一中圆角。
- 高度：按钮 40（触控设备 44）；图标按钮 40×40（触控 44×44）；位置条 32。
- 间距：4 的倍数，面板内边距 20（手机 16），卡片间距 12。
- 字号：站名 18/600；正文 15/1.75 行高（手机 15/1.7）；辅助 13；等宽数字用网站的 Geist Mono，数字一律等宽并开启 tabular-nums。
- 阴影：只在浮层（菜单、结算卡）使用一层柔和阴影；面板不用阴影，用底色区分。
- 动效：150~220 ms，ease-out；面板展开 240 ms；减少动态效果时全部改为瞬时。

### 2. 整体框架

- **进入化身数据后，网站顶栏隐藏**，化身模式全屏接管（保留浏览器返回键 / Esc 退出）。左上角换成一枚深色“← 返回整机拆解”文字按钮 + 路线名“一次访存”，承担退出功能；原来的白色“退出”按钮删除。
- **画面区**：四角只保留两组浮层：左上（返回 + 路线名 + 当前部件），右上（视角切换、沉浸、更多），均为半透明深色玻璃底（#12151c 80% + 背景模糊 12px，若不支持模糊则不透明）。浮层高度一致、对齐网格。
- **侧栏**：底色 #12151c，与画面区之间 1px 分割线；内容分成三段，固定在侧栏的上、中、下：
  1. 顶部“站点头”：站号徽章（“02 / 11”，等宽、主色）+ 站名（18/600）+ 本站耗时（右对齐，“+1 ns”，弱文字），下方一条可点的分段进度（11 段，当前段主色、已过段次文字色、未到段描边色；悬停 / 长按显示站名；点击跳站）。
  2. 中部可滚动“讲解区”：数据外壳卡片 → 讲解正文 → 结论句卡片（单独一张浅底卡片，左侧 3px 语义色边，命中绿 / 缺失红）→ 考点链接（改为“相关考点”小标题 + 文字链接列表，不再是按钮样胶囊）。
  3. 底部固定“操作区”：岔路（如有）+ 主控制（上一站、播放 / 暂停、下一站主按钮），自动巡航 / 手动游走放进播放按钮旁的分段开关（两个选项，当前项高亮）。删掉侧栏头的“›”重复按钮和底部画面控制条，画面底部不再有任何控件，画面完整。
  - 内容少时，中部讲解区与底部操作区之间不留空洞：操作区固定在底，讲解区靠上，中间留白属于正常留白但不超过 40 像素时可接受；若超过，则把“这是什么？”内容以折叠段落形式放进讲解区末尾（“展开看：TLB 是什么”），填满且有用。“小地图”移入“更多”菜单和画面左下角的一个小图标按钮。

### 3. 数据外壳卡片重新设计

- 改为“地址条”：一条完整的等宽数字地址，按字段用语义色下划线 / 底色分段，字段名写在每段下方的小字里（“标记 17 位”“组号 3 位”“偏移 12 位”），像教科书里的地址格式图。
- 当前站用到的字段高亮，其余字段降到次文字色。
- 下方一行解释改为次文字 13 号，句首对齐地址条。
- 画面里的对应位置（TLB 的“查找标记 0x00080”、当前组号、L1 的标记）用同一语义色，形成对应。

### 4. 岔路选择

- 自动判断模式：只显示一张“判断结果”卡片：“TLB 缺失 → 去主存查页表”，左侧红色竖条，另一个选项以弱文字一行显示“（若命中：直接得到页框号）”。不再画成两个按钮。
- “我来判断”模式：两个大选项卡片，未选时同样风格，选后正确的变绿、错的变红并给一句解释；整个卡片可点，44 像素以上。

### 5. 画面内文字板与标签

- 文字板统一为“深色玻璃屏”：底 #141821 85% 不透明，细描边 rgba(255,255,255,0.12)，圆角，标题行与表头用次文字色，数据用主文字色等宽字体；当前比较的行用主色描边 + 浅主色底；结果出来后命中行变绿描边、缺失时只在表头右侧出现一枚红色“缺失”徽章，行本身不全部变红。无效位 V=0 用红色字，有效位正常色。
- 修复文字板背面 / 边框的 z-fighting（绿色残边）：检查重叠平面，用 polygonOffset 或拉开间距。
- TLB 左侧组列表：8 组都写组号（0~7），当前组高亮，其余弱文字，不再是空白块。
- 场景标签统一为小型深色胶囊，字号随屏幕密度换算后不小于 12，与侧栏同字体同颜色体系；不在焦点范围内的标签（如“回程通道 → 寄存器”“缺失 → 去主存查页表”牌子）在非相关站隐藏。
- 非焦点物体：已有 40% 降亮，再加上在当前站隐藏与本站无关且出现在画面边缘的大件物体（如岔路门洞只在岔路站及前后一站显示）。
- 场景背景：保持深色，但为 CPU 内部、TLB / MMU、内存三个区域各定一个极低饱和度的环境色调（例如 CPU 偏冷蓝、内存偏暖灰），地面加一层很淡的网格以提供空间感；删掉无意义的零散竖线和光点，或降低到几乎不可见。不加辉光后处理。

### 6. 手机

- 竖屏：画面占上 55%，下方抽屉；抽屉顶部一个小拖动条（36×4 胶囊）替代“展开”大按钮，点击或上拉展开；站点头一行（站号 + 站名 + 耗时），地址条自动换行而不截断；底部操作区固定：上一站图标、播放图标、下一站主按钮（占剩余宽度）、更多图标，四个按钮同高同圆角。
- 横屏（高度 < 500）：右栏宽 38%，内容只保留站点头、地址条（可换行缩小）、正文和底部同一套操作按钮；进度改为站点头里的“02 / 11”加一条细进度线；返回与更多放在画面左上 / 右上浮层，不放在侧栏顶部。
- 折叠屏和平板竖屏沿用竖屏版式，抽屉内容更多行。

### 7. 菜单、结算卡与其他浮层

- “更多”菜单：深色浮层，分组（视图：视角、小地图、文字版；设置：参数、讲完自动继续、减少动态、字幕大小），每项左图标右文字，开关用统一的 Switch 组件。
- 结算卡：与侧栏同一视觉体系，标题、总耗时大号等宽数字、分项耗时条形图（TLB / 页表 / Cache / 主存，用语义色），下方“再走一次”“换个参数”“查看考点”三个按钮（一个主按钮，两个次按钮）。
- 参数面板、文字版：同一套表单与排版样式。

### 8. 无障碍与交互

- 全部按钮有可见焦点环（2px 主色外描边，偏移 2px）。
- 进度分段可用键盘左右切换，读屏读出“第 2 站，共 11 站，查快表 TLB”。
- 颜色语义不单靠颜色：命中 / 缺失同时有文字或图标。
- 对比度：所有文字对其底色 ≥ 4.5:1，大字 ≥ 3:1，用脚本实测并记录。

## 五、不变的东西

- 不改模拟逻辑、数值、站点顺序与讲解内容（只允许为了版式把结论句拆出来、把“这是什么”合并进讲解区，文字本身不改）。31 条模拟单测与 v18 的 ride-audit 全部保持通过。
- 不改网站其他页面的外观。
- 不引入新的大型依赖（不引入 UI 组件库）；图标用内联 SVG。
- 文字原创，网站上不出现技术说明和任何辅导书品牌、作者、来源痕迹；来源扫描为零。
- 不重写 Git 历史；Prompt 和内部工作文件不部署。

## 六、执行步骤

1. 通读 v18 的 RideMode.tsx、ride.css、rideScene.ts、three/*，列出所有界面元素与其样式来源；截取 v18 在 6 个代表视口（393×732、852×273、820×1060、1210×680、1366×640、1920×960）的第 1、2、3、8、9 站和结算卡作为“改前”。
2. 定义 --ride-* 设计变量，重写 ride.css；把散落的内联样式收拢。
3. 重做框架：隐藏网站顶栏、左上返回、右上工具组、侧栏三段式、删除画面底部控制条与重复按钮。
4. 重做地址条、岔路卡片、进度分段、结论卡片、相关考点、更多菜单、结算卡。
5. 画面内：文字板新配色与状态逻辑、修 z-fighting、TLB 组号、场景标签统一、无关物体隐藏、区域环境色与淡网格。
6. 手机竖屏 / 横屏版式。
7. 跑 ride-audit（遮挡、字号、触控、标签不重叠）并新增检查：对比度、按钮高度一致、画面底部无控件、同一功能入口唯一。
8. 每个视口截图，用 read_file 逐张看，和“改前”拼成对比图；自评清单：层级、对齐、留白、颜色语义、一致性、可读性，每项有问题就改，至少迭代两轮。
9. typecheck、lint、vitest、build、check:sources、responsive-audit 全部通过；提交 `v19: data ride UI redesign`；按 v18 流程部署（d13.sh，BUILD_ID=v19-<hash>）；线上三个尺寸复测截图，线上敏感词扫描（含 legacy 资源，需逐个文件抓取）为零。

## 七、验收标准

- 进入化身数据后屏幕上没有亮白色大块；主按钮只有一个且为主色；“下一站”只有一个入口。
- 侧栏不存在超过 40 像素的无意义空洞（电脑、平板）。
- 地址条字段颜色与画面中对应数值颜色一致。
- 文字板默认不出现红色底；红色只出现于无效位、缺失徽章、被替换行。
- 无 z-fighting 残边；非相关场景物体与标签不出现在画面中。
- 所有文字对比度达标；按钮高度统一；触控目标 ≥ 44。
- v18 的 ride-audit 全部视口全部通过，无 JS 错误，无横向溢出。
- 人工看图：每张截图在缩小到一半时仍然能一眼分辨“看哪里、读哪里、点哪里”。

## 九、逐站视觉状态说明

为了让每一站的画面和侧栏讲的是同一件事，执行时为每站定义“视觉状态”，并在代码里集中配置：

- 第 1 站（虚拟地址诞生）：寄存器组为焦点，基址寄存器高亮为主色描边；侧栏地址条全部字段为灰，只有完整地址亮起；结论卡片为中性色（无命中缺失之分）。
- 第 2 站（查 TLB）：TLB 文字板为焦点，组号字段青绿、标记字段琥珀；画面表格中“第 2 组”和“查找标记”用相同颜色；比较完成后表头出现红色“缺失”徽章，结论卡片左边条为红。
- 第 3 站（岔路）：两个门洞只在本站显示，被选中的门洞亮起，另一个降亮；侧栏为判断结果卡片。
- 第 4 站（总线飞行）：侧栏收为一行，画面无文字板，背景网格缓慢后移表现速度（减少动态时静止）。
- 第 5、6 站（页表两级）：当前楼层表项用主色描边，索引字段在地址条与表项中同色；基址 + 索引 × 4 的算式在结论卡片里以等宽字体显示。
- 第 7、8 站（物理地址与拆分）：地址条从虚拟地址平滑切换为物理地址，页框号字段为紫色，然后再按 Cache 的标记 / 组号 / 块内地址重新分段着色。
- 第 9 站（L1 比较）：当前组 4 行，逐行比较时当前行主色，比较后若不匹配，该行标记数字闪一下红色后恢复，全部比完后表头出现“缺失”徽章；脏位 D=1 用琥珀色。
- 第 10、11 站（L2 与替换）：被替换的行显示红色删除线淡出，新块绿色描边飞入，LRU 计数变化用短促的数字滚动。
- 结算：画面退为全景并降亮，结算卡居中。

## 十、设计取舍说明

- 隐藏网站顶栏是这次最大的改动。理由是化身数据是沉浸式学习模式，顶栏的登录、注册、导航在此刻没有用处，却最抢眼。退出入口保留在左上角并支持 Esc 与浏览器返回，学生不会迷路。
- 删除画面底部控制条，把全部操作收进侧栏底部，是为了让画面成为完整的一块，同时让“看画面、读侧栏、点侧栏底部”形成固定的视线路径。手机上抽屉底部的操作区承担同样的角色。
- 颜色语义统一后，学生在不同站看到同一种颜色就知道它指的是同一类字段，这比任何装饰都更能体现设计质量。
- 如果某项改动在实际截图中显得更乱，以截图观感为准回退，并在报告里说明。
