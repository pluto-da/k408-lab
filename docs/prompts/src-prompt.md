# 408 学习站 · 去除辅导书痕迹与版权合规改写 · 执行 Prompt

## 一、站长原话

> 不能让别人发现咱们是用王道的书来弄的，改的时候用王道的书弄可以，因为涉及版权等之类的问题，官方的可以，优化下吧。

## 二、深度剖析：站长真正要什么

### 1. 背景

网站在建设过程中，把一套市面上流行的 408 辅导书（四本复习全书，2027 版）作为内部参考：用它的目录确定章节划分和考点范围，用它的口径统一一些有争议的约定（例如 KMP 的 next 数组下标、散列表 ASL 失败是否计空位、位示图编号从 0 还是从 1 开始），部分实验的预设数据也直接取自书中例题。这在开发阶段完全没问题——站长说“改的时候用王道的书弄可以”，意思是**内部参考可以，但对外不能留痕**。

### 2. 为什么必须处理

辅导书是有著作权的出版物。目录编排、例题、原创讲解文字、图表都受保护。网站公开上线、面向考研群体传播后，如果：

- 页脚直接写着“内容依据某某 2027 四本复习全书目录整理”；
- 实验预设按钮名就叫“某某例题（100）”“某某 8 顶点无向图”；
- 考点说明、易错点、提示文字里反复出现“某某口径”“按某某写法”；
- 网页源代码的注释里写着“口径：某某考研 / 严蔚敏”；
- 例题的数字、图结构、序列和书里一模一样；

那么任何人（包括出版方）只要打开页面或按 F12 查看源代码，就能明确认定内容来源，网站会面临侵权投诉、下架甚至索赔的风险，也会影响网站的口碑（“抄书的”）。站长要的是：网站呈现为一个**依据官方考试大纲、历年公开真题和计算机学科通用知识独立编写**的学习工具。

### 3. “官方的可以”是什么意思

可以公开引用、标注来源的内容：

- **全国硕士研究生招生考试计算机学科专业基础考试大纲**（教育部教育考试院发布的 408 考试大纲）：考查目标、考试形式、试卷结构（数据结构 45 分、组成原理 45 分、操作系统 35 分、计算机网络 25 分）、各科的考查内容条目。考纲是官方公开文件，网站可以按考纲的章节组织内容，并明确写“依据 408 考试大纲”。
- **历年 408 统考真题**：真题由官方命题并公开，网站已经在核实后标注“20XX 年真题”，可继续保留，但题干要用自己的话复述或只取考点，答案解析必须自己写，不能照搬任何辅导书的解析。
- **RFC、IEEE 754 等国际标准**，以及计算机学科通用的定理和公式（香农定理、奈奎斯特定理、Amdahl 定律、n₀ = n₂ + 1 等）：公理性知识不受著作权保护，可以自由使用，但讲解文字必须是自己写的。

### 4. 本次要达到的效果

1. 网站所有对外可见的地方（页面文字、按钮、提示、预设名称、页脚、SEO 元数据、页面标题）不出现任何辅导书名称、出版机构名称、作者名称或“某某口径”字样。
2. 所有可以被下载查看的代码（`public/legacy/js` 下的 JS 是原样发布的，注释和字符串都能被人看到；CSS 同理）中不出现上述字样。
3. 章节结构改为依据官方考纲，页脚改写为“依据 408 考试大纲与历年公开真题整理”。
4. 直接取自辅导书的例题数据（预设序列、图结构、权值、页面访问串等）替换为自己设计的数据，或替换为可核实的历年真题数据并标注真题年份。
5. 口径差异的说明改为中性表述：“常见约定”“多数教材的约定”“近年真题的约定”，必要时同时给出两种约定，让学生“看题目怎么说”，不点名任何书。
6. 讲解文字中与辅导书原文高度相似的句子要改写成自己的语言。
7. 内部开发留下的痕迹也一并清理：单元测试的用例名、提交记录说明里的文字、部署包、服务器上残留的文件。
8. 功能和正确性不受影响：所有实验、图解、性质的计算结果在新数据下仍然正确，测试全部通过。

## 三、现状排查结果（2026-10-11）

在仓库中全文检索辅导书相关名称，发现以下几类痕迹（不含 node_modules 和构建产物）：

### 1. 页面可见文字（最高风险）
- `body.html` 页脚：“内容依据王道 2027 四本复习全书目录与 408 考纲整理 · 仅供个人复习”。
- 实验预设按钮名称：磁盘调度“王道例题（100）”；DFS / BFS“王道 8 顶点无向图”；Prim / Kruskal“王道 6 顶点（权值和 15）”；拓扑排序“王道 AOV（5 顶点）”、关键路径“王道 AOE（6 事件 8 活动）”；Floyd“王道 3 顶点”；建堆图解“王道例题”。
- 散列表实验的口径选项：“王道口径”（选项值 wd）；拉链法提示“只计与关键字的比较，空指针不计（王道）”。
- Floyd 提示文字：“path 约定按王道”。
- KMP 考点笔记：“王道 / 严蔚敏写法”。
- 性质与公式里的适用条件和易错点：建堆比较次数、图的度数和、B 树高度、记录型信号量、位示图编号、TCP 拥塞控制等条目中的“王道口径”“王道、汤小丹教材”“汤小丹教材用从 1 开始……王道和多数真题按从 0 开始”。

### 2. 代码注释（任何人查看源代码可见）
- `08-lab.js`：“Reno as in 王道”。
- `15-lab-cn.js`：“谢希仁 / 王道规则”。
- `19-lab-ds1.js`、`22-proc-ds.js`、`24-prop-ds.js` 文件头：“教材口径：王道 / 严蔚敏”。
- `21-lab-ds3.js`：“王道写法”；`22-proc-ds.js`：“约定（王道）”；`24-prop-ds.js`：“王道口径”。

### 3. 内部痕迹
- 单元测试用例名称：`labds2.test.ts`、`labds3.test.ts`、`procds.test.ts` 中的“王道 8 顶点例题”“王道 AOE”“王道口径”“王道例题”等。
- Git 提交历史中共有 47 处包含该名称的改动（仓库没有配置远程仓库，没有推送到 GitHub 等公开平台，风险较低，但部署时不能把 .git 带上服务器）。
- 工作目录中的开发文档（各轮 prompt 与 docx、从辅导书 PDF 提取的目录文本 outline_0 ~ 3）只在内部，不随网站发布，但要确认没有被打包或部署。
- 构建产物 `dist` 会原样复制 `public/legacy`，修改源文件后重新构建即可消除。

### 4. 隐性痕迹（需要人工逐条判断）
- **章节编排**：四门课的章节划分、章节名称、每章的考点顺序，当初按辅导书目录整理，可能与书的目录高度一致（例如数据结构 8 章、组成原理 7 章、操作系统 5 章、计算机网络 6 章）。需要对照官方考纲重新确定章节名称和顺序。
- **例题数据**：除了名称里写明的预设，其他“教材序列”“默认数据”也可能来自书中例题（如磁盘调度的“98, 183, 37, 122, 14, 124, 65, 67”起始 53 实际上是操作系统教科书中通用的经典示例，出处广泛，可保留但不要冠以任何书名）。
- **讲解与易错点文字**：章节“核心考点”“易错”提示、实验考点笔记、性质的推导与易错点，如有与辅导书原文逐字或近乎逐字相同的句子，需要改写。
- **口诀与独有表述**：辅导书特有的口诀、记忆方法、独创的分类说法，如果出现在网站中，要替换为通用表述或自己的说法。

## 四、改写规则

### 1. 名称与口径
- 一律删除“王道”“王道考研”“王道论坛”“王道训练营”等字样，以及任何具体辅导书名称。
- 教科书作者名（严蔚敏、汤小丹、谢希仁、唐朔飞等）也不再出现在对外内容中。这些是正式出版的教材，按理可以引用，但为了避免“对照某本书整理”的观感，统一改为中性说法。
- “王道口径”改为“常见约定”或具体描述约定本身。例如：
  - “王道口径：空位计 1 次” → “约定 A：探测到空位也计 1 次比较（近年真题常用）”。
  - “位示图王道口径 0 表示空闲” → “常见约定：0 表示空闲、1 表示已分配；也有题目反过来，以题目为准”。
  - “汤小丹教材从 1 开始，王道和多数真题从 0 开始” → “行号、列号有从 0 开始和从 1 开始两种约定，近年真题多从 0 开始，做题时以题目给出的为准”。
  - “TCP Reno（王道口径 cwnd = 新 ssthresh）” → “Reno 快恢复：cwnd 设为新的 ssthresh（408 真题的常用约定）”。
- 散列表实验中选项值 `wd` 改为语义化的值（如 `count`），并保证本地存储或链接参数里的旧值兼容或安全忽略。

### 2. 例题与预设数据
- 名称里带书名的预设，全部重新设计数据：自己构造的图、序列、权值，满足同样的教学目的（例如 Prim / Kruskal 预设要能体现“两种算法加边顺序不同、总权值相同”，关键路径预设要有多条关键活动），并重新计算正确答案，更新测试中的期望值。
- 如果某个预设能找到对应的历年真题（例如某年真题考过的关键路径图、页面访问串、散列表数据），可以改用真题数据，预设名改为“20XX 年真题”，前提是年份和数据经过核实；无法核实的一律用自己设计的数据，预设名叫“示例一”“示例二”“稠密图”“含零入度多分支”等描述性名称。
- 通用经典示例（如磁盘调度 53 起始序列、Belady 异常的经典访问串 1,2,3,4,1,2,5,1,2,3,4,5）属于学科通用素材，可保留，名称用“经典示例”。

### 3. 章节结构
- 以官方考纲为准，重新核对每门课的章节名称与范围。章节名称使用考纲中的表述或通用的学科名称（如“线性表”“栈、队列和数组”“树与二叉树”“图”“查找”“排序”），不使用辅导书特有的章节标题。
- 删除仅在辅导书中存在、考纲没有的章节划分方式（例如书中“归纳总结”“本节试题精选”这类栏目名称不应出现）。
- 页脚改为：“依据全国硕士研究生招生考试 408 考试大纲与历年公开真题整理 · 仅供个人学习交流”。

### 4. 讲解文字
- 对每条核心考点、易错提示、实验笔记、性质推导与易错点逐条检查，如与辅导书原文雷同，按“先理解、再用自己的话写”的方式改写：改变句式、换用自己的例子、加入网站独有的交互说明（“拖动滑块看看……”）。
- 优先保证正确性：改写后由第二个人（或第二轮检查）对照考纲知识点核对一遍，不能因为改写引入错误。

### 5. 代码与内部痕迹
- 注释中的书名全部删除，改为描述约定本身（例如“约定：front 指向队头元素，rear 指向队尾元素的下一个位置”）。
- 测试用例名称同步改为中性描述。
- 不重写 Git 历史（仓库未公开，重写有风险），但在部署流程中确认只上传构建产物，服务器上不存在 .git、源码、开发文档和辅导书 PDF；如服务器上已有残留，清理掉。
- 确认构建产物中没有 source map 泄露原始注释；如有，关闭或不上传。
- 工作目录中的 outline 文本、辅导书 PDF 只作内部参考，不复制进仓库。

## 五、执行步骤

1. **自动扫描**：写一个检查脚本（例如 `scripts/check-sources.mjs`），在源码、public、构建产物中检索一份敏感词清单（辅导书名称、出版机构、作者名、“口径”“写法”与书名的组合、辅导书栏目名称），输出文件与行号；把它加入测试或 lint 流程，以后新增内容时自动拦截。
2. **逐类修改**：先改页面可见文字和预设名称，再改代码注释，再改测试名称，最后处理章节结构和讲解文字。
3. **数据替换**：为每个需要更换的预设设计新数据，手工算出答案，写入测试，跑通实验与图解。
4. **相似度复查**：对讲解文字做人工抽查，重点是章节核心考点、易错提示和 56 条性质的易错点。
5. **构建与部署**：重新构建，检查 dist 中扫描为零；部署后在线上抓取页面 HTML 和全部 legacy JS，再扫描一次；检查服务器目录没有多余文件。
6. **回归验证**：全部单元测试、类型检查、lint、构建通过；Playwright 打开实验室，所有实验和图解可以逐步执行，所有性质可以打开。

## 六、验收标准

1. 对仓库源码（排除 node_modules）、构建产物和线上全部可下载资源执行敏感词扫描，结果为零。
2. 页脚、页面标题、SEO 描述中只出现“408 考试大纲”“历年真题”等官方来源。
3. 所有原先带书名的预设都已替换，新数据经过测试验证，答案正确。
4. 口径说明一律中性，学生依然能看到两种约定的区别。
5. 章节名称与官方考纲一致，没有辅导书特有的栏目名称。
6. 单元测试、类型检查、lint、构建全部通过；线上 `/`、`/lab`、`/pc`、`/api/health` 返回 200；实验、图解、性质功能正常。
7. 服务器上只有运行所需的构建产物和后端程序，没有源码、Git 仓库、开发文档或参考书文件。

## 七、注意事项

- 这是合规整改，不是简单的“查找替换”。名称删除很容易，真正的风险在于例题数据和讲解文字的雷同，要花主要精力在这两处。
- 改写不能牺牲正确性。408 题目对约定非常敏感，删掉书名之后，约定本身必须写得更清楚，否则学生会困惑。
- 已经核实的真题年份标注保留；未核实的依旧写“典型题”。
- 本次不改变网站的视觉和功能结构，只改内容与来源表述。
- 这份整改与正在进行的多设备适配、目录折叠改版涉及同一批文件，三项工作按顺序进行，避免互相覆盖。

## 八、敏感词清单（扫描脚本使用）

扫描脚本至少包含以下词条，按需扩充：辅导书品牌名及其拼音（含大小写与缩写）、该品牌的论坛与训练营名称、其他常见 408 辅导书品牌名、“复习全书”“复习指导”“四本书”“本节试题精选”“归纳总结”“答案与解析”等辅导书栏目名称、主流教科书作者姓名（对外内容中不点名）、“某某口径”“某某写法”“某某例题”这类“名称 + 口径 / 写法 / 例题 / 规则”的组合。扫描范围包括：`apps/web/public`、`apps/web/src`、`apps/web/index.html`、`apps/api/src`、`packages`、构建产物 `apps/web/dist`，以及线上抓取的页面和全部脚本。扫描结果为零才允许部署，脚本接入 `pnpm test` 或单独的 `pnpm check:sources` 命令。

## 九、预设替换清单

| 位置 | 原预设 | 替换要求 |
|---|---|---|
| 磁盘调度实验 | 带书名的例题（起始 100） | 自行设计一组 8 ~ 10 个磁道号的序列，起始磁道和方向不同于经典示例；保留“经典示例（53）” |
| DFS / BFS 实验 | 带书名的 8 顶点无向图 | 自行设计 8 顶点无向图，包含回边和多个分支，DFS 与 BFS 序列明显不同 |
| Prim / Kruskal 实验 | 带书名的 6 顶点图（权值和 15） | 自行设计 6 ~ 7 顶点带权图，两种算法加边顺序不同，有相同权值的边以演示选择顺序 |
| 拓扑排序 | 带书名的 AOV（5 顶点） | 自行设计 6 顶点 AOV，存在多种合法拓扑序 |
| 关键路径 | 带书名的 AOE（6 事件 8 活动） | 自行设计 6 ~ 7 事件、8 ~ 10 活动的 AOE 网，至少两条关键路径或一处活动时间余量为 0 的非直观情况 |
| Floyd | 带书名的 3 顶点 | 自行设计 4 顶点有向图，至少一次通过中转点缩短路径 |
| 建堆图解 | 带书名的例题 | 自行设计 8 ~ 10 个关键字，建堆过程有多次下沉 |
| 置换—选择排序图解 | 测试中称为书中例题的数据 | 检查是否来自书中，是则替换为自己设计的输入，保证得到两个以上初始归并段 |
| 散列表实验 | 口径选项“某某口径” | 改为“空位计 1 次（真题常用）”“空位不计”两种中性选项，默认值不变 |

每个新预设都要手工算出完整答案（遍历序列、最小生成树加边顺序、关键活动、最短路径矩阵等），写进单元测试作为期望值，并在页面上逐步运行一遍确认动画与答案一致。

## 十、风险分级与处理顺序

- **一级（立即处理）**：页面上直接可见的书名（页脚、预设按钮、选项、提示、考点笔记、性质条件与易错点）。这些任何访客都能看到，是最直接的证据。
- **二级（同批处理）**：源代码注释和字符串里的书名，以及与书中完全相同的例题数据。懂技术的人或出版方查看源代码时能看到。
- **三级（本轮处理并持续关注）**：章节编排和讲解文字的相似度。这类风险隐性但影响长期，需要逐条人工改写并对照考纲。
- **四级（内部治理）**：测试名称、提交历史、工作目录文档、服务器残留文件。不对外，但要确保不随部署泄露。

## 十一、以后新增内容的规范

整改完成后，以后每次新增实验、图解、性质或考点内容，都遵守以下规范：参考资料只在内部使用；对外文字一律自己撰写；例题数据自己设计或使用核实过年份的真题；约定差异用中性表述；提交前运行来源扫描；页脚与关于页只列官方来源。这条规范写进仓库的贡献说明（例如 `CONTRIBUTING.md` 中“内容来源”一节），也作为之后每一轮 Prompt 的固定要求。

## 十二、对外表述

网站的关于页、页脚、首页说明、SEO 描述统一使用以下口径：本站内容依据全国硕士研究生招生考试计算机学科专业基础（408）考试大纲组织，参考历年公开真题与计算机学科通用知识独立编写，动画实验与图解为本站原创，仅供个人学习交流。如发现内容错误或侵权问题，欢迎通过页脚邮箱联系，我们会及时核实处理。这段话既说明了来源的正当性，也给出了权利人的联系渠道，体现善意，降低争议升级的可能。

## 十三、完成定义

整改完成时，站长自己按 F12 打开实验室，在“源代码”面板里全文搜索辅导书名称，搜不到任何结果；随便点开任意一个实验的预设按钮，看到的是“示例一”“经典示例”或核实过年份的真题名称；章节名称与官方考纲一致；页脚只写官方来源。同时所有测试通过，所有功能照常可用。交付时附上整改前后的扫描结果对比和修改清单。

## 十四、分工与核对

整改分两轮完成：第一轮由执行者按清单修改并自查；第二轮换一个视角做独立复核，专门挑三类问题：是否还有漏网的名称、新预设的答案是否正确、改写后的讲解是否引入了知识性错误。两轮都通过后再部署上线。
复核时发现的问题当场修复，并把问题类型补充进扫描脚本或测试，防止以后重复出现。
整改是一次性的，规范是长期的。
