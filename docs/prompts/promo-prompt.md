# 二、受众深度分析

## 2.1 谁在看

核心受众是准备计算机学科专业基础（408）的考研学生：大三下到大四上的在校生占大头，另有一部分是跨考生和在职二战、三战的考生。他们的共同点是时间紧、科目多、焦虑感强，刷短视频的时段集中在午休、晚饭后和睡前，单条视频的耐心通常只有两三秒——前 3 秒决定他们划不划走。

次级受众包括：计算机专业正在学组成原理、操作系统、计算机网络的本科生（期末复习刚需）；给学生讲课、想找直观演示材料的助教和老师；以及对“电脑里面到底发生了什么”有好奇心的泛科技爱好者。

## 2.2 他们真正的痛点

1. **抽象，想象不出来。** 408 四门课里最折磨人的不是记忆量，而是“看不见”：虚拟地址怎样一步步变成物理地址，快表没命中之后页表怎么查，Cache 的组号、标记位到底从地址的哪几位切出来；进程什么时候被切换、信号量每一步怎么加减；拥塞窗口为什么突然掉到一半；排序每一趟到底谁和谁交换。课本只有静态插图，脑子里转不动，就只能硬背结论。
2. **背了就忘，题型一变就懵。** 死记的结论没有画面支撑，换个参数、换个问法就不会了。比如页大小从 4 KB 改成 8 KB，页内偏移位数怎么变；Cache 从直接映射改成四路组相联，地址怎么重新划分。缺的不是公式，而是“亲眼看它变一次”的经验。
3. **资料碎片化，找演示难。** 网上的动画零零散散，有的只有一个算法，有的要下载软件，有的要付费，手机上还打不开。考生需要一个四门课都覆盖、随时能开、按考点组织的地方。
4. **成本敏感。** 学生预算有限，对“免费”“不用注册”“手机就能看”极其敏感，这三点是降低尝试门槛的关键。
5. **焦虑与疲惫。** 长时间刷题让人麻木，他们会被“有点好玩”“有点酷”的东西吸引——一台能拆开的电脑、一个第一人称的数据旅程，本身就有新鲜感。

## 2.3 他们对宣传片的心理预期

他们反感浮夸的营销腔和“保过”“提分”式承诺，信任真实界面、真实操作。所以短片要**少吹多演**：用实录画面证明“真的能动、真的能点”，旁白像一个靠谱的学长在旁边指给你看，而不是广告播音。

# 三、核心卖点（按说服力排序）

1. **动画演示，一步一步看清楚。** 站内有 39 个动画实验、36 个过程图解、56 条性质与公式，覆盖数据结构、计算机组成原理、操作系统、计算机网络四门课。每个实验都能单步、播放、调速、换数据，例如排序（冒泡、插入、快速、堆、归并）、页面置换、TCP 拥塞控制、Cache 地址映射、Dijkstra 最短路径等。
2. **整机拆解 3D。** 一台可以旋转、可以逐个部件拆开的电脑：机箱、主板、处理器、内存、显卡、硬盘……把“计算机组成”从书页搬到眼前。
3. **化身数据，第一人称走完一次访存。** 观众“变成”一个虚拟地址，从执行单元出发，依次经过快表（TLB）、页表、一级缓存等站点，每一站都有讲解、有判断、有耗时；走完弹出结算卡，分项列出每一类部件花了多少纳秒。这是全片最有记忆点、最独特的卖点，要给最多的时长和最好的镜头。
4. **参数可调。** 页大小、页表级数、快表是否命中、页是否在主存、L1 容量、块大小、相联度、查找方式、各级时延都能改，改完重走一遍，结果马上不同——对应“题型一变就懵”的痛点。
5. **手机、平板、电脑都能用。** 响应式页面，竖屏手机也能完整操作。
6. **免费在线，不用注册。** 打开浏览器输入网址即可使用。

卖点表达的优先级：竖屏版以 3（化身数据）为高潮、1 为主体、2 为惊喜、5 与 6 为收束；横屏版在此基础上把 4（参数可调）单独成段。

# 四、叙事结构

采用“痛点钩子 → 解法亮相 → 三段递进演示 → 高潮 → 利益收束 → 行动号召”的六拍结构：

1. **钩子（0～3 秒）**：直接抛出考生最熟悉的那几个词——页表、快表、高速缓存——配合一帧最“炫”的 3D 访存画面（发光的寄存器方块与“R2 + 8”地址计算），屏幕中央大字“背了十遍，还是想象不出来？”。不放片头 logo，不做铺垫。
2. **解法亮相（约 3～8 秒）**：首页实录，站名与口号“408 四门课，拆开来学”清晰出现。
3. **递进演示一：动画实验**：排序柱状图正在一趟一趟交换，切到页面置换或拥塞控制，强调“按一下下一步”。
4. **递进演示二：整机拆解 3D**：一台电脑在暗场中被展示、部件被拆开。
5. **高潮：化身数据**：第一人称镜头，地址条上的虚页号、页内偏移被切开；依次经过快表、页表、一级缓存；最后结算卡弹出。
6. **利益收束**：参数面板、多设备、免费。
7. **行动号召**：干净的片尾卡，站名 + 网址 154.8.183.93，旁白读出网址，停留不少于 3 秒。

情绪曲线：开头略带“被戳中”的共鸣 → 中段好奇、惊喜 → 高潮“原来是这样”的通透感 → 结尾轻松、有行动力。

# 六、两种画幅的构图规范

## 6.1 竖屏 1080×1920

- 素材以手机视口（393×852，像素比约 2.75）实录，得到约 1081×2343 的原始帧，按宽度铺满 1080，竖向在原始帧中选取 1920 高的取景窗，必要时缓慢平移取景窗跟随画面重点。少量横屏素材（3D、化身数据）在竖屏中以“上下深色底 + 中部放大裁切”的方式使用，裁切中心对准主体。
- **安全区**：顶部 0～140 像素可能被状态栏与平台标题覆盖，标题文字放在 150～420 像素区间；底部 1920 往上约 420 像素（即 y>1500）是平台文案、进度条和按钮区，不放关键信息；右侧约 140 像素宽是点赞、评论、分享图标列，字幕与标题水平居中但整体宽度不超过 860 像素，并向左偏移约 30 像素。
- 字幕基线放在 y≈1340～1480 区间，单行不超过 15 个汉字，最多两行，白字 + 半透明深色圆角底板。

## 6.2 横屏 1920×1080

- 素材以 1920×1080 桌面视口实录，原生分辨率，不放大。
- 字幕放在底部，距下边缘约 80 像素，单行不超过 24 个汉字，最多两行；标题卡放左上或居中。
- 保留四周 5% 的标题安全边距。

# 七、旁白风格

- 声音：年轻、清亮、可信的普通话声线，像一位讲题很清楚的学长或学姐，语速略快于日常（约每秒 5 个字），句尾不拖腔。
- 语气：开头一句带一点“被戳中”的共鸣和调侃；介绍功能时干脆、具体，用动词说话（“点一下”“拆给你看”“冲进”）；高潮段语速稍快、情绪上扬；片尾放慢，网址一字一顿读清楚。
- 读法：英文缩写一律改用中文说法读出（TLB 读作“快表”，Cache 读作“高速缓存 / 缓存”，L1 读作“一级缓存”），数字读作中文（“四零八”“三十九个”“一五四点八点一八三点九三”），避免合成语音念英文出错；屏幕字幕可保留英文缩写，便于考生对应考点。
- 制作：按镜头切段合成，每段单独生成音频，按实际时长反推画面时长，保证“说到哪、画面就到哪”。

# 八、音乐风格

- 风格：轻快、干净的电子 + 钢琴氛围，带一点科技感的琶音和柔和的鼓点，节奏约 110～120 BPM，大调，明亮但不吵。
- 结构：前 3 秒以一个清脆的音头切入（配合钩子），中段铺稳定律动，高潮段（化身数据）加厚一层琶音或打击乐，片尾在最后一个和弦上自然收尾，不戛然而止。
- 授权：只使用明确为 CC0 或明确免版税可商用的曲目，并记录来源与授权条款；若无法确认授权，则自行用程序合成原创配乐，版权归制作方，从根本上避免版权风险。
- 混音：旁白出现时音乐自动压低（侧链闪避，压低约 8～12 dB，起效 20 毫秒左右、释放 300 毫秒左右），旁白空隙时音乐自然回升；整片响度 -14 LUFS（综合响度），真峰值不超过 -1 dBTP。

# 九、节奏与剪辑要点

- 平均镜头时长 2～4 秒，不出现超过 6 秒不变化的画面；静帧素材一律加缓慢推拉（每秒缩放不超过 2%），避免“幻灯片感”。
- 剪辑点尽量落在音乐的强拍或旁白的句读上。
- 每个卖点只说一次，不重复；画面与旁白同步出现，不让观众“先听后看”。
- 禁止黑屏、加载转圈、报错弹窗、空白页、鼠标乱晃等穿帮画面；实录前等待页面完全就绪。

# 十、开头 3 秒钩子设计

- 第一帧就是全片最好看的画面之一（3D 寄存器与地址计算的发光线框），而不是 logo 或纯色背景。
- 第一句话直接点名考生最怕的三个词，加一个反问，制造共鸣：“页表、快表、高速缓存，背了十遍，脑子里还是一团雾？”
- 大字标题与旁白同步弹出，字号足够大（竖屏不小于 72 像素），即使静音刷到也能看懂。

# 十四、素材采集与制作流程

1. **实录准备**：分别以竖屏手机视口和 1920×1080 桌面视口打开线上站点，每个页面等加载条、模型和动画全部就绪后再开始录制；首页、实验室、整机拆解、化身数据四个入口各录一遍。实验室挑选排序、页面置换、TCP 拥塞控制、Cache 地址映射等画面变化明显的实验，按下“播放”后连续录制十秒以上，留足剪辑余量。
2. **化身数据**：从第一站“虚拟地址诞生”开始，以巡航方式逐站前进，每站到达后停留数秒拍下稳定画面，同时连续录下站与站之间的镜头运动；走完全程后拍下结算卡。另开参数面板拍一张清晰画面。
3. **三维画面**：三维场景渲染较重，如实时录制出现掉帧，就改为在镜头稳定后截取高清静帧，再在剪辑中用缓慢推拉和交叉溶解营造运动感，宁可慢而稳，不要卡顿。
4. **旁白**：按分镜逐段合成，记录每段实际时长，以“旁白时长 + 呼吸留白”确定每镜时长，再回填画面。
5. **合成**：画面、标题卡、字幕在同一条时间线上逐帧合成，字幕直接烧录进画面；音乐按总时长生成或裁切，在旁白段落自动压低后与旁白混合，最后统一做响度标准化。
6. **导出与自检**：导出两版成片与两张封面，抽帧拼联系表检查，测量响度，发现问题回到对应环节修正。
