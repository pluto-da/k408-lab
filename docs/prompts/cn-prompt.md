计算机网络在 408 里 25 分：选择题 33–40 共 8 道，外加 1 道 9 分左右的综合题。综合题近十年几乎都围绕三类：一是“给一个网络拓扑和抓包或路由表，问 IP 分组怎么转发、地址怎么填、NAT 怎么改”；二是“滑动窗口 / 拥塞窗口 / 信道利用率怎么算”；三是“从访问一个网页出发，按时间顺序说清楚 DNS、ARP、TCP、HTTP 各发了什么报文”。选择题则大量考 CRC、编码、CSMA/CD 退避、IP 分片、最长前缀匹配、DHCP、ARP、DNS、交换机自学习、RIP 等“看得见过程的”考点。

所以计网这一块要补的，正好也是两种东西：**能改数据、反复算的动画实验**，和**按时间顺序看报文怎么走的过程图解**。

## 二、深度剖析：站长真正要什么

1. **计网的难点在“过程”和“谁先谁后”。** 学生背得出 ARP、DNS、DHCP 的定义，但一到综合题就乱：先 DNS 还是先 ARP？ARP 问的是谁的 MAC？请求是广播还是单播？跨网段时目的 MAC 写谁？NAT 改的是源地址还是目的地址？所以图解必须是“时序 + 拓扑”的：在一张简化拓扑上，每一步只发一个报文，报文沿链路走过去，旁边写清楚这个报文的关键字段（源/目的 IP、源/目的 MAC、端口、标志位），以及收到的一方怎么处理、表项怎么变。
2. **计算题要能自己换数字。** CRC、IP 分片、最长前缀匹配、编码波形、退避时间、滑动窗口，考试都是“给数字让你算”。动画实验必须带输入：自己填数据位和生成多项式、填总长度和 MTU、填目的 IP、填比特串，结果按你的数字一步一步算出来，中间过程完整可见，最后给出答案。
3. **滑动窗口必须“看得见丢包”。** 停等、GBN、SR 三种协议的区别，课本靠文字讲很抽象。最有效的是：同一组帧、同一个丢包位置，切换三种协议对比——GBN 超时后从丢的那帧开始全部重发，SR 只重发丢的那一帧、接收方缓存乱序帧，停等每次只能有一帧在路上。还要显示窗口在序号轴上怎么滑动，以及发送窗口、接收窗口大小的限制（GBN 发送窗口 ≤ 2^n − 1，SR 发送窗口 + 接收窗口 ≤ 2^n）。
4. **与现有内容不重复、能衔接。** TCP 拥塞控制、子网划分、三次握手已经有，新内容不再重做；但“访问一个网页”图解要把三次握手作为其中一环串起来，最长前缀匹配实验要与子网划分呼应。
5. **手机好用。** 站长主要在安卓手机上看，所有图解沿用上次的画布（窄屏可横向滑动、当前部件自动滚进视野），实验的输入框和按钮要适合手指操作。

## 三、范围

### A. 动画实验（放在“动画实验”区，计网分组）

1. **滑动窗口：停等 / GBN / SR。** 参数：序号位数（默认 3 位，序号 0–7）、发送窗口、接收窗口、要发的帧数、丢失的帧（可填一个或多个序号，也可丢 ACK）。画面：上方发送方序号轴（已确认 / 已发未确认 / 可发 / 不可发 四种颜色，窗口框住一段），下方接收方序号轴，中间是时序线，帧和 ACK 沿斜线飞过去，丢失的画叉。每一步一个事件：发送、到达、丢失、超时、重传、累积确认、缓存乱序帧、交付上层。统计：总发送帧数、重传帧数、用时（以 RTT 为单位）。窗口参数不合法时提示规则（GBN 发送窗口 ≤ 2^n − 1，SR 接收窗口 ≤ 2^(n−1)）。
2. **CSMA/CD 与二进制指数退避。** 两个站同时发送：载波监听、发送、冲突检测、强化干扰、退避。输入：第几次冲突 k、争用期 2τ（默认 51.2μs）、随机数 r。显示 r 的取值范围 [0, 2^min(k,10) − 1]，退避时间 = r × 2τ，16 次冲突放弃；另给出最短帧长 = 2τ × 数据率 的计算（以 10Mb/s 以太网为例：512 bit = 64 字节）。
3. **CRC 校验计算。** 输入数据位串和生成多项式（如 1101 或 x³+x²+1），按模 2 除法逐步展示：在数据后补 r 个 0，每一步异或，商位和余数一行一行写出来，最后得到 FCS 和发送的位串；还要能输入“接收到的位串”验证余数是否为 0。
4. **IP 分片。** 输入数据报总长度、首部长度（默认 20B）、MTU、DF 位。计算每片的数据长度（必须是 8 的倍数，最后一片除外）、总长度、片偏移（以 8 字节为单位）、MF 标志，表格展示每一片，并画出原数据在各片中的切分位置。DF=1 且超过 MTU 时，给出“丢弃并返回 ICMP 差错报告”的结果。
5. **最长前缀匹配与路由转发。** 给一张可编辑的路由表（目的网络 / 前缀长度 / 下一跳 / 接口，默认 5–6 条，含默认路由），输入目的 IP，逐条用掩码与运算比较，显示二进制下前缀是否相同，匹配的项中选前缀最长的，得到下一跳和转发接口；没有匹配时走默认路由。
6. **数字编码。** 输入比特串，同时画出非归零 NRZ、反向非归零 NRZI、曼彻斯特、差分曼彻斯特四种波形，逐位动画，标出每一位中间是否跳变、位开始处是否跳变；说明曼彻斯特编码的约定（站内默认采用谢希仁教材“位中间高→低表示 1”的画法（IEEE 802.3 规定恰好相反：低→高表示 1），提供一键切换，以题目为准），以及曼彻斯特编码的波特率是比特率的两倍。
7. **RIP 距离向量算法。** 给一个 4–5 个路由器的小拓扑，路由器 C 收到邻居 B 发来的距离向量后，逐条按“距离 +1、下一跳是否相同、是否更短”的规则更新自己的路由表；再演示“坏消息传得慢”：某链路断开后两路由器互相学到的距离逐轮 +1 直到 16（不可达）。

### B. 过程图解（放在“过程图解”区，新增“计算机网络”一组）

1. **数据封装与解封装。** 主机 A 的应用层报文向下经过运输层（加 TCP 首部，源端口 / 目的端口）、网络层（加 IP 首部，源 IP / 目的 IP）、数据链路层（加帧首部和帧尾，源 MAC / 目的 MAC，FCS）、物理层（比特流）；经过路由器时只解封到网络层、重新封装新的帧（MAC 地址改变、IP 地址不变、TTL 减 1）；到主机 B 再逐层解封。字段节点逐步长出来。
2. **访问一个网页的全过程。** 主机首次上网、只知道网关 IP 和 DNS 服务器 IP：ARP 解析网关 MAC → DNS 查询（UDP 53）得到 Web 服务器 IP → TCP 三次握手（80 / 443）→ HTTP 请求 → HTTP 响应 → 连接释放。每一步标出所用协议、源目的地址和端口。
3. **DNS 解析：递归查询与迭代查询。** 主机 → 本地域名服务器 → 根 → 顶级域（.com）→ 权限域名服务器，两种模式对比报文数量和谁在“替谁问”，并说明主机到本地 DNS 一般是递归、本地 DNS 向外一般是迭代，以及缓存命中时直接返回。
4. **ARP 地址解析：同一网络与跨网络。** 同网段：广播 ARP 请求（目的 MAC 全 F）、目标单播回应、双方更新 ARP 缓存；跨网段：主机只解析默认网关的 MAC，帧交给路由器，路由器再在下一个网络里解析。
5. **DHCP 获取地址。** DHCP Discover（广播，源 IP 0.0.0.0，目的 255.255.255.255，UDP 68→67）→ Offer → Request（仍为广播，告诉其他服务器选了谁）→ ACK，租期与续租。
6. **NAT 地址转换。** 内网主机 192.168.1.2:5000 访问外网服务器，NAT 路由器把源地址改成公网地址和新端口（NAPT），在转换表中登记；响应回来时按表把目的地址改回内网地址。
7. **以太网交换机自学习与转发。** 四台主机连在一台交换机上，交换表初始为空；依次发几帧，演示“记录源 MAC 与入端口”“目的 MAC 不在表中就泛洪（除入端口）”“在表中就单端口转发”“目的与源在同一端口则丢弃”，以及表项老化。
8. **电子邮件的发送与读取。** 发件人用户代理 → SMTP → 发送方邮件服务器 → SMTP → 接收方邮件服务器 → POP3 / IMAP → 收件人用户代理；说明 SMTP 是“推”、POP3 是“拉”，以及 MIME、基于万维网的邮件（HTTP）。
9. **ping 与 traceroute（ICMP）。** ping：ICMP 回送请求 / 回答；traceroute：依次发送 TTL = 1、2、3 的数据报，每个路由器 TTL 减到 0 时返回 ICMP 时间超过报文，最终目的主机返回端口不可达，从而得到路径上每一跳。

## 六、验收标准

1. CRC：数据 101001、生成多项式 1101，余数 001，发送 101001001；接收 101001001 校验余数为 0；接收 101001011 余数非 0。
2. IP 分片：总长 4000B、首部 20B、MTU 1500 → 三片，数据长度 1480 / 1480 / 1020，片偏移 0 / 185 / 370，MF 1 / 1 / 0，总长 1500 / 1500 / 1040。
3. 最长前缀匹配：表中同时有 /16 和 /24 都匹配时选 /24；都不匹配时选默认路由 0.0.0.0/0。
4. 编码：比特串 0110 的曼彻斯特波形每位中间都跳变；差分曼彻斯特中“0”在位开始处跳变、“1”不跳变。
5. CSMA/CD：k=3 时 r ∈ [0, 7]；k=12 时 r ∈ [0, 1023]；k=16 时放弃发送；10Mb/s、2τ=51.2μs 时最短帧长 64 字节。
6. 滑动窗口：3 位序号、GBN 发送窗口 7、丢第 2 帧时，超时后重发 2 及其后已发的所有帧；SR 只重发第 2 帧，接收方缓存 3、4…并在 2 到达后一起交付；GBN 窗口设 8 时给出不合法提示。
7. RIP：B 通告“到 N 距离 3”，C 原来到 N 距离 5 且下一跳不是 B → 更新为距离 4、下一跳 B；原下一跳就是 B 时无论远近都更新。
8. 9 个图解每个模式都能从头走到尾再退回，所有步骤引用的部件和连线存在（单元测试覆盖）。
9. 手机 390×844 视口：无页面横向溢出，输入、按钮可点；类型检查、lint、单元测试、构建全部通过；部署后 `/`、`/lab`、`/pc`、`/api/health` 返回 200。

## 七、内容质量要求

- 报文字段写全写准：ARP 请求是广播帧、ARP 回应是单播；DHCP Discover 源 IP 0.0.0.0、目的 255.255.255.255；DNS 用 UDP 53；HTTP 默认 TCP 80；SMTP TCP 25；POP3 TCP 110；ping 用 ICMP 回送请求（类型 8）与回答（类型 0）；traceroute 依赖“时间超过”（类型 11）。

## 八、逐步脚本（实现时每一步的文字依据）

### 滑动窗口实验
以 3 位序号、GBN 发送窗口 4、发送 8 帧、第 2 帧丢失为例：第一步发送方连续发出 0、1、2、3 号帧，窗口框住 0–3；第二步 0 号帧到达，接收方期待号正好是 0，交付上层并回送 ACK1（GBN 采用累积确认，ACK n 表示 n 以前的都已收到）；第三步 1 号帧到达，回 ACK2；第四步 2 号帧在链路上丢失，画叉；第五步 3 号帧到达，但接收方期待的是 2，GBN 接收窗口为 1，只能丢弃 3 号帧并重复发送 ACK2；第六步发送方收到 ACK1、ACK2，窗口向前滑到 2–5，可以继续发 4、5；第七步 2 号帧的计时器超时，发送方回退，把 2、3、4、5 全部重发；之后依次到达、确认，直到全部发完。切换到 SR 后：接收窗口为 4，3 号帧到达时被缓存，回送对 3 号帧的单独确认 ACK3；超时后只重发 2 号帧；2 号帧到达后，2、3、4……连续的一段一起交付上层，接收窗口跳过它们。停等协议则每次只能有一帧在路上，序号只用 0 和 1 交替。统计区实时显示：已发送帧数、其中重传帧数、已交付帧数、所用时间（以单程传播时间为单位），并给出信道利用率的提示公式 U = 发送时间 /（发送时间 + RTT）。

### CRC 实验
数据 101001、生成多项式 1101（r = 3）：第一步在数据后补 3 个 0 得到被除数 101001000；第二步被除数前 4 位 1010 与 1101 异或得 0111，商位记 1；第三步下移一位得 1110，再与 1101 异或得 0011，商位记 1；依此类推，商位为 0 时与 0000 异或，只做移位；最后余数 001 就是帧检验序列 FCS，发送 101001001。接收端用同一生成多项式去除收到的整串，余数为 0 则无差错（CRC 只能检错，不能纠错；数据链路层只保证“无比特差错”，不保证可靠传输）。

### IP 分片实验
总长 4000B、首部 20B → 数据 3980B；MTU 1500 → 每片最多 1480B 数据（1480 是 8 的倍数，可以直接用；若不是要向下取到 8 的倍数）；第一片数据 0–1479，片偏移 0/8 = 0，MF = 1；第二片数据 1480–2959，片偏移 1480/8 = 185，MF = 1；第三片 2960–3979 共 1020B，片偏移 370，MF = 0。每片都带 20B 首部，标识字段与原数据报相同，分片只在目的主机重组。

### 最长前缀匹配实验
目的地址 128.96.39.10：逐条与路由表项比较，128.96.39.0/25 用掩码 255.255.255.128 相与得 128.96.39.0，相同，匹配，前缀 25；128.96.39.128/25 相与得 128.96.39.0，与 128.96.39.128 不同，不匹配；128.96.40.0/25 不匹配；192.4.153.0/26 不匹配；默认路由 0.0.0.0/0 总是匹配，前缀 0。在所有匹配项中选前缀最长的 /25，从接口 0 转发。

### RIP 实验
C 原来的路由表：到 N1 距离 3 下一跳 A，到 N2 距离 5 下一跳 B，到 N3 距离 2 下一跳 D；收到 B 的通告“N1 4、N2 2、N4 3”。先把通告中的每个距离加 1、下一跳改为 B，得到 N1 5、N2 3、N4 4；逐条比较：N1 原来 3 经 A，新的 5 经 B，下一跳不同且更长，不更新；N2 原来下一跳就是 B，直接用新的 3 替换；N4 原来没有，直接加入；N3 不在通告中，不变。每条结论都配一句规则说明。

### 访问网页图解
第一步主机检查 Web 服务器域名的 IP 不在缓存，DNS 服务器 IP 不在本网段，所以要先把 DNS 查询发给默认网关，于是先发 ARP 广播询问网关 MAC；第二步网关单播回应自己的 MAC；第三步主机把 DNS 查询（UDP，目的端口 53）封装成帧，目的 MAC 写网关、目的 IP 写 DNS 服务器；第四步 DNS 回应 Web 服务器 IP；第五至七步 TCP 三次握手（SYN、SYN+ACK、ACK）；第八步 HTTP GET 请求；第九步 HTTP 200 响应；第十步四次挥手释放连接或保持持续连接。每一步的帧都标出：源 MAC、目的 MAC、源 IP、目的 IP、源端口、目的端口。

### CSMA/CD 实验
第一步站 A 监听信道空闲，开始发送；第二步站 B 在 A 的信号到达之前也监听到空闲，开始发送；第三步两路信号在中途相遇发生碰撞，碰撞信号向两端传播；第四步 A、B 在发送过程中检测到碰撞，立即停止发送并发送 32 位（或 48 位）强化干扰信号，让所有站都知道发生了碰撞；第五步各自进入退避：第 k 次碰撞后，从 {0, 1, …, 2^min(k,10) − 1} 中随机取 r，等待 r × 争用期；第六步退避结束重新监听，若再碰撞则 k 加 1，退避范围翻倍；碰撞 16 次仍不成功就放弃并向上层报告。考点：一个站最多经过 2τ 才能确定没有碰撞，所以帧的发送时间不能小于 2τ，否则来不及检测到碰撞；以太网规定最短帧长 64 字节，凡小于 64 字节的都是因冲突而异常中止的无效帧。

### 数字编码实验
以比特串 0110 为例：NRZ 用高电平表示 1、低电平表示 0，整位不跳变，无法从信号中提取时钟；NRZI 遇 1 翻转、遇 0 不变；曼彻斯特每一位中间都有跳变，既表示数据又作同步时钟，代价是所需带宽加倍；差分曼彻斯特每位中间都跳变只作同步，数据看位开始处：0 有跳变、1 无跳变，抗干扰更好。

### 交换机与 ARP、DHCP、NAT 图解
交换机：A 发给 B 的帧到达端口 1，交换机记下“A 在端口 1”；查表找不到 B，向除端口 1 外的所有端口泛洪；B 回帧时记下“B 在端口 2”，查表发现 A 在端口 1，单端口转发；以后 A 与 B 之间的帧都只在两端口之间转发，C、D 收不到。ARP 跨网段：主机发现目的 IP 不在本网络，于是查默认网关的 MAC；帧的目的 MAC 是路由器接口的 MAC，而 IP 首部的目的地址始终是最终主机。DHCP：所有报文都是 UDP，客户端用 68 端口，服务器用 67 端口；Request 用广播是为了通知所有提供了 Offer 的服务器它选择了谁。NAT：转换表一项记录“内网 IP:端口 ↔ 公网 IP:端口”，外网主机看到的永远是公网地址，所以内网主机不能被外网主动访问，除非事先配置端口映射。

### DNS、电子邮件、traceroute 图解
DNS 迭代查询：主机向本地域名服务器发出递归查询；本地服务器先查缓存，没有则问根服务器，根服务器不替它往下查，只回答“去问 .com 顶级域名服务器，地址是……”；本地服务器再问顶级域名服务器，得到权限域名服务器的地址；最后问权限域名服务器得到 IP，缓存并回答主机，共 8 个报文。递归查询模式下，每一级服务器都替下一级去问，结果沿原路返回，报文同样往返但负担集中在上层服务器，所以根服务器一般不接受递归查询。电子邮件：发件人用户代理用 SMTP 把邮件推送到发送方邮件服务器，邮件进入发送队列；发送方服务器作为 SMTP 客户与接收方服务器建立 TCP 连接，发送邮件；收件人用户代理用 POP3 或 IMAP 从接收方服务器拉取邮件；SMTP 只能传 7 位 ASCII，非 ASCII 内容需 MIME 编码。traceroute：源主机发出 TTL = 1 的数据报，第一个路由器把 TTL 减为 0，丢弃并回送 ICMP 时间超过报文，于是得知第一跳；TTL = 2 得到第二跳，依此类推；到达目的主机时，因为使用了一个不可能的 UDP 端口，目的主机回送 ICMP 端口不可达，源主机据此知道已经到达终点。
