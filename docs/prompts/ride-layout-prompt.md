# 化身数据 · 画面遮挡深度优化（手机 / 平板 / 电脑）· 执行 Prompt

## 一、站长原话

> 这都挡住了，再深度优化下。（附平板横屏截图）
> 手机端和电脑端也是。

## 二、截图逐项诊断

截图来自安卓平板横屏浏览器，页面可视区域约 1210 × 600 CSS 像素（浏览器标签栏、地址栏和站点顶栏一共吃掉了约 290 物理像素，3D 区域只剩屏幕高度的三分之二左右）。当前停在路线一第 2 站“查快表 TLB”，问题如下：

1. **字幕面板压在画面正中央**。字幕卡宽约 1760 物理像素、高约 340，从屏幕左侧 330 一直铺到 2090，横跨了几乎整个画面宽度，正好压住 ALU、CU 控制器和 TLB 表格的下半部分。讲的是 TLB，但 TLB 本身被讲解文字挡住了，这是最根本的失败：讲解和画面在抢同一块地方。
2. **数据外壳（虚拟地址胶囊）压在 ALU 上**。胶囊悬浮在画面中部偏下，下方的 ALU 字样只露出一半，胶囊和字幕卡又叠在一起，形成三层堆叠。
3. **TLB 表格与寄存器组重叠**。场景里 TLB 的文字板放在 z = -14、高度 3.3，寄存器组也在镜头前方偏上的位置，从当前镜头看过去，TLB 表格正好藏在 R3、R4 两个寄存器后面，“MMU · 快表 TLB”标签直接压在 R3 上（部署时已经发现，但没修）。表格本身也太远太小，8 组 × 4 路的内容在平板上完全读不出来——这一站最该看清的东西反而最看不清。
4. **右侧控件堆叠**。小地图、前进 / 后退两个圆形按钮在右侧纵向挤成一列，前进按钮紧贴小地图下沿；按钮又和字幕卡右端相邻，触控时容易误点。
5. **顶部工具条与左上信息卡**。退出、视角、参数、文字版、设置五个按钮和小地图、左上位置卡都占用了画面上方 1/4，导致真正的“观察窗口”被压缩到中间一条窄带，然后又被字幕卡和外壳压掉一大半。
6. **底部控制条**。上一站、暂停、到站、自动巡航 / 手动游走，加上进度条，占了底部约 1/6 高度。
7. **整体结论**：可视 3D 面积里，被 HUD 覆盖的比例超过 60%，剩下的部分正好不是讲解对象所在的位置。现有的“画面中心挪到 HUD 以外”的逻辑（`setViewOffset`，按 bottom × 0.42 偏移）只是把投影中心稍稍上移，没有把讲解对象真的放进空白区，也没有考虑顶部控件和右侧控件。

站长补充“手机端和电脑端也是”：说明这不是平板一个断点的问题，而是整个 HUD 布局思路的问题。手机竖屏可视面积更小，手机横屏高度只有 330 左右；电脑 1366 × 768 的浏览器扣掉标签栏和顶栏后，也只有 600 多像素高。

## 三、站长真正要什么

站长要的不是“把字缩小一点”或“把面板透明一点”，而是：**在任何设备上，当前站点正在讲的那个东西（TLB 表格、Cache 组、页表楼层、寄存器）必须完整、清楚、不被遮挡地出现在画面里，讲解文字放在不挡它的位置，控件不互相打架。** 第一人称的价值在于“看见”，看不见就失去了这个功能的意义。

可以拆成四个目标：

- **焦点可见**：每一站的讲解对象（下称“焦点对象”）在屏幕上的包围盒不与任何 HUD 元素相交，且占据足够大的面积，文字在该设备上可读（换算后的字号不小于 12 CSS 像素）。
- **讲解不挡画**：字幕从“画面中央的大卡片”改为“贴边的侧栏或底栏”，并且画面渲染区域主动避开它，而不是被它盖住。
- **控件有序**：所有按钮集中到少数几个固定区域，互不重叠，触控目标不小于 44 像素，彼此间距不小于 8 像素。
- **沉浸可选**：学生可以一键收起全部 HUD，只看画面；也可以收起字幕只留一行标题。

## 四、设计方案

### 1. 从“覆盖式 HUD”改为“分区式布局”

把化身数据的屏幕划分成固定区域，3D 画面只渲染在“观察窗口”里，HUD 放在观察窗口之外（或只以很窄的条带贴边覆盖）：

- **宽屏（宽高比 ≥ 1.3，含平板横屏、电脑、大屏）**：右侧为讲解侧栏，宽度 clamp(300px, 28vw, 420px)，从上到下依次是：站点标题与序号、讲解正文（可滚动）、考点标签、“这是什么？”、数据外壳（地址拆分胶囊移入侧栏，以卡片形式显示）、小地图（可折叠）。左侧剩余区域全部是观察窗口。底部一条高 56 像素的控制条只横跨观察窗口宽度，按钮靠左排列，进度条嵌在控制条里。顶部工具按钮（退出、视角、参数、文字版、设置）收为观察窗口右上角的一个紧凑按钮组，图标 + 短字，高度 40，必要时“参数 / 文字版 / 设置”合并进“更多”菜单。左上位置卡缩成一行细条（部件 · 真实时间 · 演示时间），半透明，高度不超过 32。
- **竖屏（宽高比 < 0.8，手机竖屏、平板竖屏）**：上半部分为观察窗口，高度约 55%~60%；下半部分为讲解抽屉，默认显示标题 + 两到三行正文，可上拉展开为全文，下拉收成一行标题。数据外壳放在抽屉顶部第一行（与标题同行或紧随其后），不再悬浮在画面上。控制条放在抽屉底部。小地图收进“更多”。
- **矮横屏（高度 < 500，手机横屏）**：观察窗口占左侧约 62%，右侧讲解栏占 38%，讲解栏内正文可滚动，控制按钮以图标形式排成一行放在讲解栏底部；顶部工具组收成一个“更多”按钮。确保讲解栏至少显示标题 + 4 行正文（当前只露 2~3 行）。
- **中间比例（0.8 ~ 1.3，折叠屏展开、方形窗口）**：按竖屏处理，但观察窗口占 60%。

实现方式：渲染器的画布尺寸直接设为观察窗口大小（或保持全屏画布，用 `setViewport` / `setScissor` 只渲染观察窗口区域），而不是用 `setViewOffset` 偏移投影中心。这样 3D 场景和 HUD 在物理上就不重叠，透视也不会因为偏移而变形。布局由 CSS Grid 决定，`ResizeObserver` 监听观察窗口元素的尺寸，变化时同步更新相机的宽高比和渲染区域。

### 2. 焦点对象自动取景

只把 HUD 挪开还不够，镜头还必须把焦点对象完整放进观察窗口：

- 每个站点在路线配置里声明焦点对象（例如第 2 站为 TLB 文字板 + 对应组的高亮框，第 L1 站为当前组的 4 行，页表站为当前楼层的表项）。
- 到站时，计算焦点对象的世界包围盒，根据观察窗口的宽高比和相机视场角，求出能完整容纳包围盒、四周各留 8% 边距的相机距离和朝向，平滑过渡到该位置（“到站取景”）。飞行过程中仍沿曲线前进，只有到站停下时执行取景。
- 取景后做一次遮挡检测：从相机向焦点包围盒的若干采样点发射射线，若被其他物体（如寄存器组）挡住，则沿预设的备用方向（抬高、侧移）调整一次；仍被挡住时，把遮挡物临时淡化到 15% 不透明度。
- 文字板的分辨率与大小按观察窗口实际像素决定：保证板上最小字在屏幕上不小于 12 CSS 像素，否则推近镜头或放大文字板；在手机上为文字板使用更大的字、更少的列（例如 TLB 只画当前组的 4 项 + 一行“其余 7 组已省略”，点击可展开全部）。

### 3. 场景布局修正

- **TLB 与寄存器组错开**：把 MMU / TLB 区域放到寄存器组的侧前方或下一个独立“房间”，与寄存器组在镜头方向上不共线；“MMU · 快表 TLB”标签移到 TLB 板的正上方并与寄存器保持间距。检查 CPU 场景里所有标签（通用寄存器组、CU 控制器、ALU、L1/L2/L3）在各站镜头下互不重叠。
- **标签可读性**：3D 标签统一使用屏幕空间最小尺寸（距离远时不再缩小到不可读），并在与其他标签相交时自动隐藏次要标签。
- **当前站以外的元素降亮度**：焦点对象保持全亮，其余物体降到 40% 亮度，引导视线。

### 4. 数据外壳的重新定位

- 宽屏放在讲解侧栏顶部；竖屏放在讲解抽屉顶部。
- 若站长希望保留“悬浮在眼前”的沉浸感，可在设置里提供“外壳悬浮”开关，悬浮时也必须放在观察窗口的下边缘，宽度不超过观察窗口的 60%，并且取景计算把它占用的区域也排除在外。默认关闭。

### 5. 控件整理

- 顶部工具：观察窗口右上角紧凑按钮组（退出、视角切换为图标按钮，“更多”内含参数、文字版、设置、字幕大小、讲完自动继续、减少晃动）。
- 前进 / 后退：仅在“手动游走”模式下显示，且放在观察窗口右下角，与控制条不重叠；自动巡航模式下隐藏。
- 小地图：宽屏放入侧栏底部，可折叠；其他布局收进“更多”或以小按钮呼出浮层。
- 新增“沉浸模式”按钮（快捷键 H）：隐藏全部 HUD，只保留一个淡出的小按钮用于恢复。
- 讲解区新增“收起”控制：宽屏可把侧栏收成 48 像素的窄条（只剩站点序号和展开按钮），观察窗口随之变宽。

### 6. 讲完自动继续

截图里学生停在第 2 站需要手动点“到站 / 继续”。保留默认停下（便于阅读），但在讲解区明显位置提供“下一站”主按钮，并在设置里可开启“讲完自动继续”。

## 五、验收标准

用 Playwright 自动化验证以下视口（均在“模拟浏览器栏占用”的高度下测，即在实际窗口高度中额外扣掉 120 像素）：

- 手机竖屏 360 × 780、393 × 852；手机横屏 852 × 393、780 × 360；
- 折叠屏 673 × 841、884 × 1104；
- 平板竖屏 820 × 1180；平板横屏 1210 × 800、1180 × 820；
- 笔记本 1366 × 768、1440 × 900；桌面 1920 × 1080、2560 × 1440。

对路线一默认参数的每一站以及“缺页”变体的每一站，自动检查：

1. 焦点对象投影到屏幕的包围盒与所有可见 HUD 元素的包围盒交集为 0；
2. 焦点对象包围盒完全位于观察窗口内，且面积不小于观察窗口面积的 25%；
3. 焦点文字板上最小字的屏幕字号不小于 12 CSS 像素（通过文字板像素尺寸与屏幕投影尺寸换算）；
4. 所有 HUD 按钮两两不相交，间距不小于 8 像素，触控设备上不小于 44 × 44；
5. 3D 标签两两不相交（屏幕投影）；
6. 讲解正文在矮横屏下至少可见 4 行，竖屏抽屉默认至少 2 行；
7. 无横向溢出，无 JS 报错。

另外每个视口保存第 2 站（TLB）、L1 站、页表站、结算卡四张截图，逐张人工查看，确认肉眼看来没有遮挡、文字清楚。把检查写进 `ride-audit` 脚本，后续每次改动都能复跑。

## 六、实施步骤

1. 读 `RideMode.tsx`、`rideScene.ts`、`ride.css`、`three/chip.ts`、`three/mem.ts`、`three/layout.ts`，梳理当前 HUD 元素清单、`setInsets` / `applyOffset` 逻辑和各站镜头参数。
2. 重写布局：CSS Grid 分区，观察窗口元素 + `ResizeObserver`，渲染区域只覆盖观察窗口；删除投影偏移逻辑。
3. 站点配置增加焦点对象声明，实现到站取景、遮挡检测与淡化。
4. 修正 CPU 场景布局（TLB 与寄存器错开、标签上移、标签防重叠），检查内存场景页表楼层和 DRAM 阵列在各站下的可读性。
5. 整理控件：紧凑工具组、“更多”菜单、手动模式才显示的前进后退、沉浸模式、侧栏收起。
6. 写 ride-audit 自动检查，跑全部视口，截图逐张查看，修到全部通过。
7. 全量测试（typecheck、lint、vitest、build、check:sources、原有 responsive 审计），提交 `v18: data ride layout — no occlusion`，部署，线上在平板横屏、手机竖屏、电脑三个尺寸复测并截图。

## 七、注意事项

- 不改变模拟逻辑和讲解内容（除非为了竖屏抽屉需要更短的首句，此时只拆分不删改含义）；31 条模拟单测必须保持通过。
- 不改整机拆解原有模式和“数据旅程”的外观。
- 网站上不出现技术说明；文字原创；来源扫描为零。
- 风格保持克制：侧栏和抽屉用与现有 HUD 一致的深色半透明底、圆角和字体，不新增装饰。
- 性能：分区渲染后画布像素变少，帧率应当提高；取景计算只在到站时执行一次，不放进每帧循环。
- 减少动态效果模式下，取景直接切换，不做平滑过渡。

## 九、各站焦点对象与取景要求（路线一）

下面逐站列出焦点对象、取景要求和该站在小屏上的简化方式，执行时以此为准，并把它写进路线配置：

1. **我诞生了：一个虚拟地址**。焦点是通用寄存器组中存放基址的寄存器（截图中为 R2，值 00402A74）和 ALU 的地址加法器。取景时让 R2 与 ALU 同时出现在观察窗口中，寄存器组其余格子可以出画；数据外壳在讲解区显示加法过程“基址 + 偏移 = 0x00402A7C”。小屏简化：只显示 R1~R3 三个寄存器。
2. **查快表 TLB**。焦点是 TLB 文字板中当前组（第 2 组）的 4 项和标记比较结果。取景必须让 4 项的有效位、标记、页框号三列文字清晰可读；其余 7 组以浅色缩略行表示，不要求可读。小屏简化：文字板只画当前组 4 项，外加一行“其余 7 组已折叠”。这一站是站长截图所在站，修完后必须先拿它做对比。
3. **TLB 缺失，去主存查页表**（岔路站）。焦点是两道门洞和门上的条件文字。门洞并排放在镜头正前方，两道门的文字都完整可见；“我来判断”模式下，门本身就是可点击区域，点击范围不小于 44 像素。
4. **沿内存总线飞向内存**。飞行段，无焦点对象，HUD 应自动退到最小（讲解区只留一行标题），让学生感受“在通道里飞行”。
5. **页目录第 1 项**、6. **页表第 2 项**。焦点是当前楼层被选中的表项和它的地址计算式（基址 + 索引 × 4）。取景让当前表项居中、上下相邻各一项可见。小屏简化：只画当前项及相邻两项。
7. **得到物理地址**。焦点是外壳中的地址变换：虚页号被页框号替换。这一站以讲解区的外壳卡片为主，画面中可以保持页表楼层作为背景。
8. **物理地址拆成标记、组号、块内地址**。焦点是外壳卡片三段拆分，同时画面中出现 L1 的整体轮廓。
9. **L1 第 105 组逐行比较**。焦点是第 105 组的 4 行（有效位、脏位、标记、LRU 计数），逐行比较时当前行高亮。取景让 4 行完整可读；其余组以细线表示。
10. **L2 命中 / 逐级查找**。焦点是 L2 中命中的那一行与“整块调入 L1”的飞行动画。
11. **替换与装入**。焦点是 L1 第 105 组中被替换的那一行翻转淡出、新块飞入的过程，以及 LRU 计数的变化。
12. **数据回到寄存器**。焦点回到寄存器组，目标寄存器 R1 显示取回的数据。
13. **结算卡**。结算卡是全屏覆盖层，不涉及取景；但在矮横屏下必须可滚动，按钮不被浏览器底栏挡住。

“缺页”变体额外的站点（触发缺页中断、磁盘调页、更新页表、重新执行指令）同样声明焦点对象，要求与上面一致。

## 十、各设备的目标版式描述

### 平板横屏（站长截图场景，约 1210 × 600 可视）
观察窗口约 830 × 544，位于左侧；右侧讲解侧栏宽约 360。站点标题“2/11 查快表 TLB”在侧栏顶部，下面是外壳卡片（虚页号 0x00402 | 页内偏移 0xA7C，并标出“低 3 位 = 2  为 TLB 组号”），再下面是讲解正文和两个考点标签，侧栏底部是小地图。观察窗口里，TLB 第 2 组的 4 项占据画面中部约一半宽度，文字清楚，寄存器组在画面上沿只露一角作为背景。观察窗口底部是控制条：上一站、暂停、下一站（主按钮）、巡航 / 手动切换。右上角是退出、视角和“更多”三个按钮。

### 手机竖屏（393 × 732 可视）
观察窗口 393 × 420；下方讲解抽屉显示“2/11 查快表 TLB”、外壳卡片一行、正文前两行和“展开”。TLB 第 2 组 4 项在观察窗口里横向铺满，字号不小于 12。控制条在抽屉底部，按钮为图标加短字。

### 手机横屏（852 × 330 可视）
观察窗口约 528 × 330；右侧讲解栏约 324 宽，标题、外壳卡片、正文至少 4 行，底部一行图标按钮。顶部只有一个“更多”和一个“退出”。

### 电脑 1366 × 768（浏览器可视约 1366 × 640）
与平板横屏相同的分区，侧栏宽约 380，观察窗口约 986 × 584。鼠标悬停在焦点对象上显示提示，键盘快捷键说明放在“更多”里。

### 大屏 1920 / 2560
侧栏最大宽 420，正文字号随根字号放大；观察窗口宽阔，焦点对象占比按 25%~50% 控制，不无限放大，避免近看时文字板像素化（文字板分辨率随屏幕像素比提升）。

## 十一、风险与取舍

- **沉浸感下降的担心**：把 HUD 移出画面后，3D 区域变小，但实际可见的有效画面反而更大，因为不再被盖住。侧栏使用与画面相近的深色，视觉上仍是一个整体。
- **取景跳动**：每站自动取景可能让镜头频繁调整。要求过渡时间 0.6~0.9 秒、缓动平滑，且仅在站点之间执行；手动游走模式下，学生转头后不强制回正，只在按“到站”时取景。
- **文字板分辨率与内存**：手机上放大文字板会增加贴图内存。要求只给当前焦点文字板使用高分辨率，其余文字板使用低分辨率，切站时重绘。
- **自动检查的可靠性**：焦点包围盒依赖三维投影计算，检查脚本需要从页面暴露一个只在测试环境存在的调试接口（读取当前站焦点的屏幕矩形和 HUD 元素矩形），生产构建中不包含该接口，以免页面出现技术痕迹。
- **与原 prompt 的差异**：原 prompt 设想 HUD 覆盖在画面上、数据外壳悬浮在眼前。站长的反馈表明这种做法在真实设备上不可行，本次以“分区布局 + 焦点取景”取代，外壳悬浮保留为可选项，默认关闭。

## 十二、完成定义

站长在平板横屏、手机竖屏、电脑上打开 `/pc?ride=access`，走完路线一，每一站都能一眼看清当前讲的对象，讲解文字和按钮不挡住它，按钮不重叠；自动检查全部视口全部通过；线上部署完成并附对比截图。

## 十三、执行顺序中的检查点

第一个检查点：只完成分区布局和平板横屏的第 2 站取景，截图与站长原图并排对比，确认方向正确后再推进到其他站点和其他设备。第二个检查点：手机竖屏和手机横屏全部站点通过自动检查。第三个检查点：电脑和大屏通过，部署上线。每个检查点都要人工逐张看截图，不能只看自动检查的数字，因为数字通过但画面难看的情况同样不可接受。
